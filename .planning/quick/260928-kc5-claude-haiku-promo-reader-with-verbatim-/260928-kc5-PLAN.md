<objective>
Add a Claude Haiku 4.5 promo reader to the promo scrape job. For every scraped entry it classifies the promo and extracts its fields. A verbatim-number guard backs every number it returns, the existing pattern parsers stay the baseline and fallback, the two readings are reconciled by a pure module, and readings are cached in Postgres so each promo text is sent to the API only once.

Purpose: the pattern parsers miss new promo wordings, and those entries currently vanish or land in review with no pre-filled fields. A second, independent reading catches misses and flags parser mistakes. The verbatim guard means the model can never put an invented number into money math.
Output: the promoReading/verbatimGuard/reconcile/promoReader/readerCache/readerPass modules with tests, the promo_readings table and migration, run.ts wiring, the --no-reader flag, the workflow secret, and an opt-in live smoke script.
</objective>

verbatimGuard.ts (new, pure, decimal.js only, no floats for money):
- Export `READER_NUMERIC_FIELDS = ["boostPercent","bonusAmount","maxStake","maxWinnings","minOddsAmerican"] as const`.
- Export `type GuardedReading`. It is PromoReading minus evidence, with money fields normalized to 2dp strings, plus `droppedFields: ReaderNumericField[]`.
- Export `guardReading(reading, sourceText): GuardedReading`. For each non-null numeric field, check three things:
  1. The value is well-formed. For money, strip one leading "$", one trailing "%" and commas; the result must match /^\d{1,6}(\.\d{1,2})?$/ and is normalized with new Decimal(v).toFixed(2). For minOdds it must be an integer with |v| >= 100.
  2. evidence[field] is a non-empty string whose whitespace-collapsed, lowercased form is a substring of the whitespace-collapsed, lowercased sourceText.
  3. The normalized evidence is at most 80 characters (EVIDENCE_MAX_CHARS = 80), so an evidence string can't be a whole sentence with several numbers in it.
  4. Field-bound proof: scan the evidence for numeric tokens with regex /[+-]?\d[\d,]*(?:\.\d+)?/g (commas stripped for comparison), keeping each token's index. A token proves the field only if:
     - boostPercent: the token is unsigned, its Decimal equals the value, it is immediately followed by "%" (one optional space allowed), and the evidence contains "boost" (case-insensitive).
     - bonusAmount, maxStake and maxWinnings: the token is unsigned, its Decimal equals the value, and it is immediately preceded by "$" (one optional space allowed).
     - minOddsAmerican: the signed token equals the value (an unsigned token counts as positive), it is not followed by "%" (optional space), and it is not preceded by "$" (optional space).
  5. One occurrence per field: the proving token's absolute source position is the index of the evidence's first occurrence in the normalized, lowercased source plus the token's offset within the evidence. Guard all fields first, then drop BOTH fields whenever two fields resolve to the same absolute position.
  Any failure sets the field to null and appends it to droppedFields (requirement 2: the model never invents or relabels a number). Export EVIDENCE_MAX_CHARS. The field-binding rules close the cross-field mislabel hole the plan checker found. Without them, maxStake "50" citing "Profit Boost: 50%" would pass the guard and reach a rescued candidate.
