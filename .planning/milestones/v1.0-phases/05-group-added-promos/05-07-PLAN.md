<objective>
Phase goal (user story):

**As a** group member, **I want to** add a promo I see in my own sportsbook app and manage the ones I added, **so that** my Promos list and Opportunities feed include the promos the scrapers miss, with the same exact hedge math, visible only to me.

Management slice (part 1): a member can "Expire now" or "Delete" a promo they added from its Active row, with confirm dialogs, and it leaves Promos and Opportunities at once. Deletion is a soft delete so Done history and Total profit extracted are untouched (D-11, Research Pitfall 1: promo_completions cascades on a hard delete). Making Done rows aware of their source's state (badge + actions on Done rows) is Plan 09.

Purpose: PROMO-05 (expire, delete), D-10, D-11 (soft-delete storage rule).
Output: owner-checked db functions + two actions, dialogs + row actions on Active rows.

Orchestrator default A4 (visible at execution): soft-deleting a promo also deletes its promo_profit_observations rows; promo_completions (Done) rows are kept.
Discretion (documented): row actions show in the Promos tab only (Opportunities rows keep the badge; managing happens in Promos). Done rows (Plan 09) show Expire now/Delete but not Edit (a done promo's snapshot is frozen and it is not in the feed).
</objective>
