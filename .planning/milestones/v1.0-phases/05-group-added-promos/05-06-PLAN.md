<objective>
Phase goal (user story):

**As a** group member, **I want to** add a promo I see in my own sportsbook app and manage the ones I added, **so that** my Promos list and Opportunities feed include the promos the scrapers miss, with the same exact hedge math, visible only to me.

Second add slice: a member picks Type "Profit boost", enters a boost % or boosted odds, game(s), max stake (and optional caps/pin/expiry), saves, and sees the boost ranked in Promos and Opportunities with the existing cap-aware boost math.

Purpose: PROMO-01 (profit-boost half), D-03, D-05, D-06.
Output: boost schema branch, builder + action boost path with pin resolution, Type toggle + BoostFields UI.

Orchestrator defaults (visible at execution):
- A1: "Total payout" -> `total_payout`, "Extra winnings" -> `boost_extra` cap kinds.
- A3: when the boost is entered as "Boosted odds", One game plus a market/side pin is REQUIRED (the engine only honors a published boosted price on a pinned selection, Research Pitfall 5). This amends UI-SPEC's optional pin for that mode only; the pin Select moves into the main section in that mode with the message "Pick the exact bet this price is for." Boost % keeps the pin optional under More details.
</objective>
