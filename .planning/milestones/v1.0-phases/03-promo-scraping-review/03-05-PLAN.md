finePrint.ts: plain-text extraction only. htmlToText is a small tag-stripper for the JSON fields that carry HTML (Bally description/terms, FanDuel description): no DOM library is needed because these are short, trusted-shape marketing snippets and the output is only fed to the linear regexes below — never rendered as HTML (T-03-05-02). Regexes are simple and linear with no nested quantifiers (ReDoS guard), case-insensitive keyword families:
- stake: max(imum)?.? (bet|wager|stake), "max $N wager", "up to $N" near wager/bet; mentioned with no dollar amount = unparsed
- winnings: max(imum)? (winnings|payout|profit)
- min odds: "minimum odds", "min odds", "odds must be X or longer", "X or longer"; normalize "-+100" to +100
Amounts normalize to 2dp strings via decimal.js, never parseFloat. parseMaxWinnings takes the book's convention kind from the caller (03-RECON.md winnings_cap_kind is boost_extra for all three books); it never infers the kind from text (D-18).

exclusions.ts: classifyExclusion checks, in order: category "New Customers" or new-customer/new-user/first-bet/sign-up wording -> new_customer; deposit-bonus wording -> deposit; not-a-promo wording (pick'em, sweepstakes, giveaway, refer-a-friend, bet protect, account linking, racing/track, casino) -> not_a_promo; live-only wording -> live_only; futures/champion/"to win the" -> futures; tournament/outright wording (Presidents Cup, Masters, Open, tournament winner) -> outright; player-prop/scorer wording -> prop; SGP/SGPx/same game parlay in the title -> sgp; parlay in the title -> parlay; otherwise if the terms restrict bet types to Parlay/SGP without "single"/"any wager" -> parlay or sgp; else null. Doc comment cites D-15 and 03-RECON.md Design Implication 3 plus each book's Exclusion rules.

sportHints.ts: word-boundary regexes so "WNBA" never matches NBA. Supported map covers the five SPORT_KEYS; the unsupported list covers at least WNBA, NHL, soccer, golf, tennis, MMA/UFC, horse racing, NASCAR.
