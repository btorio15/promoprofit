### WR-01: Duplicate cron delivery can double-spend Odds API credits

**Files modified:** `src/app/api/cron/scrape/route.ts`, `src/app/api/cron/scrape/route.test.ts`, `src/lib/githubDispatch.ts`, `src/lib/githubDispatch.test.ts`
**Commit:** 787aff2 (shared with WR-03, same file)
**Applied fix:** After auth, the route calls `getDailyRunStatus()`. If `observeDone`, it dispatches with `forceMorningObserve: false` (workflow input `"false"`), so the Denver-hour gate applies and the forced refresh is not repeated. A DB error is caught and logged, and the route fails open to a single forced dispatch. Auth stays fail-closed, and the DB is not touched when unauthorized. Tests cover not-done, done, DB-throws and unauthorized. Requires human verification: with force off, the workflow's `odds:morning-observe` can still run inside the morning Denver window, since only `--force` is dropped.

### WR-02: already-ran-today has no timeout and its error path can throw

**Files modified:** `scripts/already-ran-today.ts`, `.github/workflows/scrape-promos.yml`, `src/lib/withTimeout.ts`, `src/lib/withTimeout.test.ts`
**Commit:** c21660f
**Applied fix:** `getDailyRunStatus()` is raced against a 30s timeout through a new `withTimeout` helper. `emit` is called exactly once, outside the try. The `GITHUB_OUTPUT` append is wrapped in try/catch. The workflow step has `timeout-minutes: 2`. `withTimeout` has unit tests.

### WR-03: GH_REPO is interpolated into the URL path without validation

**Files modified:** `src/lib/githubDispatch.ts`, `src/lib/githubDispatch.test.ts`
**Commit:** 787aff2
**Applied fix:** `repo` must match `/^(?!\.+\/)(?!.*\/\.+$)[\w.-]+\/[\w.-]+$/`, which rejects dot-only segments such as `../..`. Otherwise it falls back to `DEFAULT_GH_REPO`. Tests cover valid and invalid values.
