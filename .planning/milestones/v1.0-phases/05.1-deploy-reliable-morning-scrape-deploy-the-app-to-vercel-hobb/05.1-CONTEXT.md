## Implementation Decisions

### Where the scrape runs
- **D-01:** Vercel Cron does NOT run the scraper itself. A once-daily Vercel Cron hits a protected app route that triggers the existing GitHub Actions "Scrape promos" workflow via `workflow_dispatch` (GitHub REST API). Scraper code, its secrets (DATABASE_URL, ANTHROPIC_API_KEY, ODDS_API_KEY) and logs stay on GitHub, as proven today.
- **D-02:** The trigger needs a GitHub token stored as a Vercel env var — a fine-grained token scoped to this repo only with the minimum permission to dispatch workflows (Actions: read & write). The owner creates it (human step); never committed, never logged, never NEXT_PUBLIC_.
- **D-03:** The cron route must be protected so only Vercel's cron can call it (Vercel `CRON_SECRET` Authorization: Bearer check); any other caller gets 401 and no dispatch.
- **D-04:** The morning run must still execute the morning odds refresh + profit observation (currently gated inside `scripts/morning-odds-observe.ts` by `isMorningObservationWindow`, Denver hour < 10). The dispatched run should force/allow it (the workflow already has a `force_morning_observe` input) so it doesn't depend on exact minute.
- **D-05:** On failure: just log (GitHub run shows failed / Vercel function log shows dispatch error); app keeps the previous promos; manual dispatch remains available. No automatic retry beyond the backup run (D-07).

### Morning timing & backup
- **D-06:** Vercel Cron schedule in the 13:00 UTC hour (Hobby cron fires at an arbitrary minute within the hour): 7:00–7:59 AM MDT, 6:00–6:59 AM MST in winter — accepted seasonal drift.
- **D-07:** Keep exactly ONE GitHub `schedule` entry as a backup at ~15:37 UTC (~9:37 AM MDT), which skips the scrape + morning-observe if a successful scrape already happened today (Denver date). Remove the 12:07/5:07 PM (18:07/23:07 UTC) runs. `workflow_dispatch` (manual + cron-triggered) stays. The skip check must not consume Odds API credits.
- **D-08:** "Already ran today" is determined from data the app already has (e.g. latest promo scrape timestamp / credit_usage / an existing run record) — planner's choice; no new table unless unavoidable (and then owner OK per migration rule).

### Web address & sharing
- **D-09:** Free `*.vercel.app` address (exact project name depends on availability; prefer `promoprofit`). No custom domain now (possible later).
- **D-10:** Same live Neon database — existing accounts (owner, Dico1108, Joel Gaikwad) keep working; just use the new address. `APP_URL` set to the deployed URL so `npm run invite:create` prints full deployed invite links.
- **D-11:** Production must be secure for a public URL: iron-session cookie `secure` in production, SESSION_SECRET set in Vercel, all server actions keep `requireUser()`. `allowedDevOrigins` (dev-only) is irrelevant in production and stays as-is.

### How updates go live
- **D-12:** Link the GitHub repo to the Vercel project: every push to `main` auto-deploys (failed builds don't replace the live deployment). Preview deployments for other branches are fine/irrelevant.
- **D-13:** Database migrations stay MANUAL with the owner's explicit OK (`npm run db:migrate`), never run by the build/deploy. Order for schema changes: migrate first, then push.
