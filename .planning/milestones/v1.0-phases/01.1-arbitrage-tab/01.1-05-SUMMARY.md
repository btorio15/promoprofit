# Phase 01.1 Plan 05: Arb Server Contract & findArbs Action Summary

**`findArbs` server action merges cent-exact moneyline arbs (zero Odds API credits) with spread/total arbs from the extended cache into one return-%-ranked list per sport, backed by a new `src/domain/arb` contract (input schema, DTOs, badge/selection labels) and a dedicated arb fixture set.**

## Performance

- **Duration:** ~20 min
- **Tasks:** 2 completed, each as a RED (test) → GREEN (feat) TDD pair
- **Files modified:** 7 (7 created, 0 modified)

## Accomplishments

- `src/domain/arb/arbInput.ts` exports `ArbInputSchema` (money-string `totalStake` validated via decimal.js — never `parseFloat` — with `precision: "whole" | "cents"` defaulting to `"whole"`) and `DEFAULT_TOTAL_STAKE = "200.00"`, mirroring `finderInput.ts`'s validation discipline exactly (same regex, same >0/<=100000 refine pattern, same fixed error message idiom).
- `src/domain/arb/types.ts` defines the exact DTO shapes from the plan's interface contract (`ArbLegDTO`, `ArbResultDTO`, `ArbResultsBySport`, `FindArbsResponse`) — every money/percentage field a fixed 2dp string, never a number, so nothing can cross the server/client boundary through float arithmetic.
- `src/domain/arb/labels.ts` (pure, zero-I/O) provides `marketBadgeLabel` ("Moneyline" / "Spread ±X.5" / "Total O/U X.5") and `selectionLabel` (team name alone for moneylines, `${team} +X.5`/`${team} −X.5` for spreads using the U+2212 minus to match `formatAmerican`'s convention, `${side} X.5` for totals) — both fully covered by `labels.test.ts`'s 16 tests, which also cover every `ArbInputSchema` validation case.
- `src/test/fixtures/arbEvents.ts` provides `buildArbFixtureEvents` (three `cached_odds`-shaped moneyline events: (a) a unique-best-pair NBA arb hand-verified to the cent, (b) an NFL event proving D-06's different-books rule survives even when one book is individually best on both sides, (c) an MLB event with no arb anywhere) and `buildArbExtendedFixtureEvents` (two `cached_extended_odds`-shaped events: (d) an NCAAF half-point spread arb with an exact three-way price tie on one side, (e) an NCAAB total arb plus a whole-number spread line that must never surface).
- `src/app/actions/find-arbs.ts` (`"use server"`) implements `findArbs(input): Promise<FindArbsResponse>`: validates input, reads `getCachedEvents`/`getCachedExtendedEvents`/`getBonusBooks`/`getHedgeBookKeys` in parallel, returns `no_cached_odds` only when *both* caches are empty, and for `"all"` plus every `SPORT_KEYS` entry independently builds `extractTwoWayMoneylines(...).map(moneylineToArbMarket)` concatenated with `extractTwoWaySpreadsAndTotals(...)`, ranks with `rankArbs` (no slicing, no limit — D-04), and maps every opportunity through `toArbResultDTO` (`.toFixed(2)` on every `Decimal`, `marketBadgeLabel`/`selectionLabel` for display text, `tiedBookKeys` → display names, `worstCase` from the two net-profit strings differing). The file never imports `@/ingestion/odds/client` (grep-verified, count 0) and a dedicated test asserts `fetchSportOdds`/`listSports` are never called.
- All hand-derived fixture numbers (fixture (a)'s $94.00/$106.00/$6.80/3.40% whole-dollar values and $94.03/$105.96/$6.87/3.43% exact-cents values, computed independently via fraction arithmetic before implementation) matched the actual `calculateArb`/`rankArbs` output exactly on the first test run — no numeric corrections were needed.

## Decisions Made

- `ArbResultDTO` intentionally exposes only `marketBadge` (a formatted display string), not the raw numeric `line` from the domain layer — this follows the plan's interface contract literally; tests that need to assert "the whole-number line never appears" check `marketBadge` (e.g. `!== "Spread ±3"`) instead of a nonexistent `line` field.
- Fixture (d)'s three-book spread tie was deliberately designed so `findBestArbPair`'s alphabetical-bookKey tiebreak (an internal Plan 01 detail) can resolve to either candidate book as `sideA` without breaking the test — both possible winners leave exactly one other book as an exact-price tie, so the assertion (`tiedBookNames` has length 1) holds regardless of which book wins.
