## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → refreshSpreadsTotals server action | Directly callable; can trigger credit spend |
| App server → The Odds API | Outbound call with ODDS_API_KEY; response is untrusted JSON |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01.1-12 | Denial of Service (shared credit budget) | refreshSpreadsTotals | mitigate | Server-side evaluateRefreshGate on every call (warn/block/insufficient with 3× estimate), unconfirmed calls never fetch, shared refresh_lock serializes against Refresh odds and CLI; client disabled state is UX only |
| T-01.1-13 | Tampering (credit ledger) | credit recording | mitigate | Same credit_usage table + refresh.ts's finally-block recording copied verbatim (spend recorded even on partial failure, CR-01 carry-forward, no fake 0 balance) — never a second ledger |
| T-01.1-14 | Tampering (cache integrity) | purge ordering | mitigate | Purges only after full-loop success; normal refresh has zero references to extended store fns (grep gate + D-16 test) |
| T-01.1-15 | Information Disclosure | error messages / status | mitigate | safeMessage-style fixed strings only (never raw errors echoing the request URL with apiKey); status returns counts/timestamps only |
| T-01.1-16 | Tampering | refreshSpreadsTotals input | mitigate | Zod `z.object({ confirmed: z.boolean() })`; invalid → fixed error, no side effects |
| T-01.1-17 | Tampering | Odds API response | mitigate | Existing OddsEventListSchema parse in fetchSportOdds (unchanged); point validated downstream by isHalfPoint (Plan 01) |
</threat_model>
