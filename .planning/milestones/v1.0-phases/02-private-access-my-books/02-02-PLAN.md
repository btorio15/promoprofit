## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> login server action | untrusted credentials |
| any request -> proxy.ts | untrusted path + cookie presence |
| browser -> page.tsx | page render must not run for logged-out users |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-09 | Spoofing | login brute force / credential stuffing | mitigate | users.failed_login_attempts + locked_until, 5 failures -> 15-minute lock, checked before verifyPassword; persisted in Postgres (not in-memory) |
| T-02-10 | Information Disclosure | account enumeration on login | mitigate | identical "Incorrect email or password." for unknown email and wrong password; verifyAgainstDummyHash equalizes timing for unknown emails |
| T-02-11 | Elevation of Privilege | protected page reached without session | mitigate | proxy.ts redirect on missing cookie (defense in depth) + requireUser() as the first statement of page.tsx, which also catches expired/tampered cookies (RESEARCH Pitfall 3) |
| T-02-12 | Spoofing | session persists after logout on this device | mitigate | logout() calls endSession() (iron-session destroy clears the cookie) then redirects to /login |
| T-02-13 | Spoofing | stolen cookie remains valid until 30-day ttl (stateless seal cannot be revoked server-side) | accept | private 3-5 person group; httpOnly+secure+sameSite lax cookie limits theft vectors; revocation would need a session-version column — not required by D-06 |
| T-02-14 | Tampering | CSRF on login/logout server actions | accept | Next.js Server Actions enforce Origin-vs-Host check by default; all actions are same-origin |
| T-02-15 | Tampering | open redirect after login | mitigate | login/logout redirect only to fixed literals "/" and "/login"; no user-supplied return URL |
</threat_model>
