## Layout & Responsive Behavior

(Not in the base template — added because CONTEXT.md and this phase's notes require the finder to be "usable at phone width" while mobile optimization itself is deferred to DASH-06/v2.)

- **Structure:** One page, top to bottom: odds status bar (sticky) → finder form → results list.
- **Odds status bar** (sticky, full width, `secondary` surface, `border-b`): odds-age text + refresh button on one line; credit meter (label + progress bar) on the line below. Sticks to the top of the viewport on scroll so age/credits/refresh stay visible while scanning long result lists.
- **Finder form:** a single `Card`. **Mobile (< 768px, default/mobile-first):** fields stack full-width, in order: bonus book select → bonus amount → sport filter (optional) → "Find hedges" button (full width). **Desktop (≥ 768px, `md:` breakpoint):** fields lay out in a single horizontal row (`flex flex-wrap items-end gap-4`) with the button right-aligned.
- **Results list:** full-width list of compact rows (not a two-column layout — the row itself already has five data points wide enough to want full width, especially with the mono odds/currency figures). **Mobile:** each row is a stacked micro-layout (game/time line, bonus-side line, hedge-side line, profit+conversion line) inside a `Card`, min tap target 44px on the whole row (expand affordance). **Desktop (≥ 768px):** each row becomes a single horizontal line — `Game & time | Bonus side | Hedge side | Guaranteed profit | Conversion % | chevron` — in a `grid` with fixed column widths so all 10 rows align, mono figures line up vertically.
- **Row expansion:** tapping/clicking anywhere on the row (or the chevron) expands a `Collapsible` panel beneath it showing both legs' stakes and the per-outcome payout table. Only one row's math is duplicated per expand — no accordion-exclusivity requirement (multiple rows can be expanded at once).
- **Touch targets:** all inputs, selects, buttons, and the full-row expand target are minimum 40px height (`h-10`); the mobile result-row tap target is 44px minimum per row.
- **Dark mode:** class-strategy dark mode (Tailwind `dark:` + shadcn CSS variables), driven by OS `prefers-color-scheme` on first load. No manual theme-toggle control required in Phase 1 — Claude's discretion — defaulted.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge internal padding, mono-figure letter spacing adjustments |
| sm | 8px | Compact spacing: status-bar line-to-line gap, result-row internal line spacing, table cell padding |
| md | 16px | Default spacing: form field stacking (mobile), card internal padding, row-to-row gap in results list |
| lg | 24px | Section padding: form card padding, expanded-row panel padding |
| xl | 32px | Layout gaps: status bar to form, form to results list |
| 2xl | 48px | Major section breaks: page top margin to status bar |
| 3xl | 64px | Page-level spacing: bottom page margin below the results list |

Exceptions: result-row mobile tap target is 44px (not on the 8-pt scale by name but satisfies it as 8×5.5 rounds to the nearest accessible minimum — treat 44px as a fixed exception for touch targets only, consistent with the archived spec's precedent).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 400 (regular) | 1.5 |
| Body | 16px | 400 (regular) | 1.5 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 36px | 600 (semibold) | 1.2 |

- Exactly 4 sizes, exactly 2 weights (400 regular, 600 semibold) — no other sizes/weights permitted in Phase 1 UI.
- **Label (14px):** form field labels, table/column headers, odds-age and credit-meter caption text, "Same book" badge, conversion-% caption, game start-time text.
- **Body (16px):** input values, bonus/hedge side odds and team names in compact rows, empty/error state body copy, expanded-panel table cell values.
- **Heading (20px):** section titles ("Refine your search" is implicit in the form card, "Results" above the list), and — the focal number in its **collapsed** state — each row's **guaranteed profit $** figure, accent-colored, `Geist Mono`.
- **Display (36px):** reserved for the **expanded** row panel — the guaranteed profit figure is restated at Display size at the top of the expanded panel as the anchor number the per-outcome table explains. This is the only place Display size appears; it never appears twice on screen at once (only one restatement per expanded row).
- **Numeric formatting:** every dollar figure, odds value, and percentage renders in `Geist Mono` with `font-variant-numeric: tabular-nums` so figures align down the results list (desktop grid columns) and inside the expanded per-outcome table.

## Color

Both light and dark values given — the finder must work in both (per CONTEXT.md notes) and be usable at phone width.

| Role | Value (light) | Value (dark) | Usage |
|------|------|------|-------|
| Dominant (60%) | `#FFFFFF` (white) | `#09090B` (zinc-950) | Page background |
| Secondary (30%) | `#FAFAFA` (zinc-50), border `#E4E4E7` (zinc-200) | `#18181B` (zinc-900), border `#27272A` (zinc-800) | Odds status bar surface, finder form card, result-row cards, expanded-panel surface, table zebra rows |
| Accent (10%) | `#059669` (emerald-600) | `#10B981` (emerald-500) | See "Accent reserved for" below |
| Destructive | `#DC2626` (red-600) | `#EF4444` (red-500) | Refresh disabled/blocked state (<20 credits), refresh-failure alert, inline field validation errors |
| Warning (amber) | `#D97706` (amber-600) | `#F59E0B` (amber-500) | Stale-odds age text (>2h), credit-meter warning banner (<100 credits) |

Accent reserved for (exhaustive list — nothing else may use accent color):
1. Primary CTA button ("Find hedges") background/fill
2. The guaranteed-profit dollar figure in every result row (collapsed Heading-size, and expanded Display-size restatement) — the one number the whole page exists to surface
3. The active/selected chip in the sport-filter toggle group
4. Input focus ring (`focus-visible` outline) on all form controls

All other UI (labels, body text, card borders, table borders, odds figures, disabled states, the "Same book" badge) uses zinc neutrals only. The "Refresh odds" button is a secondary/outline button (not accent) — it is a frequent, low-stakes utility action, not the page's primary conversion action, so it does not compete with the profit figures or the "Find hedges" CTA for the reader's eye.

Color-palette rationale: emerald is reserved entirely for "this is money the user will actually keep," so it never has to compete with itself — one meaning, one color. Amber marks time-sensitivity/caution (stale odds, dropping credit budget) without implying a hard stop. Red marks a hard stop (refresh blocked, refresh failed, invalid input) — distinct from amber so severity is scannable at a glance in the status bar.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (form) | **Find hedges** — submits book + bonus amount (+ optional filters) and computes the ranked results list |
| Secondary CTA (odds bar) | **Refresh odds** — re-fetches from The Odds API and recomputes; label swaps to "Refreshing…" (with spinner) while in flight |
| Empty state — no inputs yet (heading) | **Enter a book and bonus amount to find your hedge** |
| Empty state — no inputs yet (body) | "Pick the book holding your bonus bet, enter the amount, and press Find hedges to see ranked conversion markets." |
| Empty state — no qualifying markets (heading) | **No qualifying markets right now** |
| Empty state — no qualifying markets (body) | "No games in the selected sport are in season this week. Clear the sport filter or refresh odds." |
| Empty state — no cached odds yet (heading) | **No odds cached yet** |
| Empty state — no cached odds yet (body) | "Press Refresh odds to pull current Colorado odds before searching — odds haven't been fetched yet." |
| Loading state (refreshing) | Status bar: "Refreshing odds…" with a spinner in place of the refresh icon; form and results list stay visible (not blocked) showing the previous cached results until the refresh resolves |
| Error state — refresh failed | "Couldn't refresh odds — the Odds API didn't respond. Try again, or keep using the odds cached {N} min ago below." + **Try again** button |
| Error state — field validation (amount) | "Enter a bonus amount greater than $0." |
| Error state — field validation (book) | "Choose the book holding your bonus bet." |
| Odds age — fresh | "Odds updated {N} min ago" |
| Odds age — stale (> 2h) | "Odds updated {N} min ago — **Refresh before betting**" (amber text + icon) |
| Credit meter — normal | "{N} of 500 credits remaining this month" (Label caption under/beside the progress bar) |
| Credit meter — warning (< 100) | Amber banner above the form: "Only {N} credits remaining this month — a refresh uses approximately {X} credits." |
| Credit meter — blocked (< 20) | Red/destructive banner, Refresh button disabled: "Only {N} credits left — refresh is disabled until next month's reset (1st)." |
| Refresh confirmation (within 15 min of last refresh) | In-page dialog, not `window.confirm`. Heading: "Odds were refreshed {N} min ago." Body: "Refreshing again will spend approximately {X} credits. Refresh anyway?" Buttons: **Refresh anyway** (accent, primary) / **Cancel** (ghost, ends the action with no fetch) |
| Same-book badge | Badge text: "Same book" — shown next to the hedge side whenever the hedge book equals the bonus book (D-17); tooltip on hover/tap: "Both legs are at the same sportsbook." |
| Conversion % caption | "Conversion" — label under/beside the percentage (profit ÷ bonus amount), never relabeled "ROI" in this phase (that label is reserved for cash/boost legs in Phase 3) |
| Per-outcome table headers (expanded row) | "Outcome" · "Stake" · "Payout" · "Net profit" |
| Sport filter — "all sports" default chip | "All sports" (selected by default; NFL / NBA / MLB / NCAAF / NCAAB chips per D-01) |
| Destructive actions this phase | **None.** The finder is enter-and-look — nothing is saved, edited, or deleted (no login, no persisted promos until later phases). The 15-minute refresh confirmation above is a **credit-spend** confirmation, not a destructive-data confirmation, and is scoped accordingly (no "type to confirm," just Refresh anyway / Cancel). |
