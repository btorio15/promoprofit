## Fixed Issues

### WR-01: Group (Statistics) observations are ranked at the viewer's precision, not "whole"

**Files modified:** `src/db/promoObservations.ts`, `src/db/promoObservations.test.ts`, `src/app/actions/get-opportunities.ts`, `src/app/actions/get-opportunities.test.ts`, `src/app/actions/get-promos.ts`, `src/app/actions/get-promos.test.ts`
**Commit:** 80f1c5c
**Applied fix:** Removed the `precision` option from `recordCurrentProfitObservations` and `computeCurrentProfitEntries`. Group ranking is now hard-coded to `"whole"`, the same as the scheduled job, so a caller can no longer pass the viewer's precision (the compiler rejects it). Both server actions stopped passing it. The tests now expect whole-precision numbers, and there is a new test showing that a cents viewer on the Dashboard passes no precision.
**Status:** fixed: requires human verification (logic change)

### WR-02: Dashboard and Promos loads write the viewer's private promos into the site-wide Statistics table

**Files modified:** `src/db/promoObservations.ts`, `src/db/promoObservations.test.ts`, `src/db/profitHistory.ts`
**Commit:** d1d258b
**Applied fix:** The group recorder now keeps only `scraped` promos, whatever list the caller passes. This matches the scheduled job's `getActivePromos(now)` visibility, and because it happens inside the recorder it covers the Dashboard, the Promos tab and the scheduled job. `loadDailyProfitHistory` also now filters on `promoVisibilityCondition()` (`addedByUserId IS NULL`), so any private-promo rows already written are hidden from the Statistics page. No schema change. Two new tests: mixed scraped and private promos record only the scraped one, and private-only records nothing.
**Status:** fixed: requires human verification (logic change)

### WR-03: The member recording rule is still written twice, so the scheduled job can drift from the Dashboard

**Files modified:** `src/ingestion/odds/morningObserve.ts`, `src/ingestion/odds/morningObserve.test.ts`, `src/db/memberFeedRecording.ts`
**Commit:** 2ae104e
**Applied fix:** `recordAllMembersObservations` now calls `recordMemberFeedObservations` and no longer has its own copy of computeMemberFeed, buildMemberObservationEntries and recordMemberProfitObservations. The helper's doc comment now names all three callers. The tests run the real shared helper on top of the existing lower-level mocks, so they still check behaviour. The whole-precision test now feeds a `cents` rankOpts and asserts that the helper forces `"whole"`. A new test shows that a write failure inside the helper is counted as `failed`.

### WR-04: The member pass and the snapshots are skipped entirely when no Odds API key is configured

**Files modified:** `src/ingestion/odds/morningObserve.ts`, `src/ingestion/odds/morningObserve.test.ts`
**Commit:** a3e92f6
**Applied fix:** Only the refresh depends on the key now. Without a key, the job logs `console.error("runMorningObservation: no Odds API key configured ...")`, sets `refreshOutcome` to `{ status: "error", message: MISSING_KEY_MESSAGE }`, and still runs the group recorder, the snapshot recorder and the member pass from cached odds. The `"missing-api-key"` skip reason is removed from `MorningObserveResult`. `scripts/morning-odds-observe.ts` needed no change because it already prints `refreshOutcome`. The tests were updated to show that every recorder runs and the log line appears.
**Status:** fixed: requires human verification (logic change)
