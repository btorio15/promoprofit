## Phase Goal

**As a** group member holding a bonus bet at a Colorado sportsbook, **I want to** enter the book and bonus amount and see the best market to convert it on and the best book to hedge at, **so that** I can lock in a guaranteed profit with exact stakes computed from real cached Colorado odds.

<objective>
Replace the fixture odds with real Colorado odds. This plan builds a quota-safe Odds API client, the credit gate, the cache writer, and the refreshOdds server action. It also adds `npm run odds:refresh`: after this plan the owner can pull live odds into the cache and immediately get real hedges in the finder. The finder UI's refresh button arrives in Plan 05. Last, a live smoke test verifies the Colorado bookmaker keys (ODDS-05).

Purpose: ODDS-01/02/04/05 server side. The finder never spends credits; only an explicit refresh does.
Output: ingestion module, refresh action, CLI scripts, and a verified book config.

Credit-cost decision (Claude's discretion per CONTEXT.md): request with `bookmakers=<7 free-tier keys>` instead of `regions=us,us2`. The Odds API docs (re-checked during planning) state that every group of 10 bookmakers counts as 1 region, and that bookmakers takes priority over regions. This covers exactly the D-15 book set for 1 credit per in-season sport instead of research's 2, which halves the monthly cost. Empty responses cost 0 credits.
</objective>
