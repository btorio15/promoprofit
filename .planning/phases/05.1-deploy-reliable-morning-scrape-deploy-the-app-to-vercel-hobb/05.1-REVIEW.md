# Phase 05.1: Code Review Report

**Depth:** standard

## Summary

The core security items hold up. The cron route fails closed when CRON_SECRET is unset. It compares the bearer token with a length check followed by `timingSafeEqual`. Neither the secret nor the GitHub token appears in any response or log. The dispatch is a single POST with the token only in the Authorization header. The DB status check is read-only and fails open. The workflow gates skips only on `github.event_name == 'schedule'`. safeAction rethrows NEXT_REDIRECT, so logout, login and redeem redirects still propagate. No blockers were found.

## Warnings

### WR-01: Duplicate cron delivery can double-spend Odds API credits

**File:** `src/app/api/cron/scrape/route.ts:19-39`
**Issue:** The header comment accepts duplicate Vercel Cron deliveries. Each delivery dispatches the workflow with `force_morning_observe=true`. `--force` bypasses the Denver-hour gate, so a duplicate run (queued behind the concurrency group) repeats the moneyline refresh and spends credits twice. The budget is only 500 credits per month. The scheduled-only skip logic does not protect dispatched runs.
**Fix:** In the route, call `getDailyRunStatus()` and skip the dispatch if `observeDone && scrapeDone`. Or have the workflow run the already-ran check for dispatches with a `source=cron` input and skip the observe when done.

### WR-02: already-ran-today has no timeout and its error path can throw

**File:** `scripts/already-ran-today.ts:15-32`
**Issue:** A hung Neon connection blocks the step until the 15-minute job timeout. The backup run then fails instead of failing open. In addition, `emit()` in the catch handler calls `appendFileSync`. If it throws, the result is an unhandled rejection and a nonzero exit, which contradicts "fails open, exit 0". If `emit` throws inside `main`, the catch handler also emits a second time and appends duplicate output keys.
**Fix:** Race `getDailyRunStatus()` against a ~30s timeout. Set `timeout-minutes: 2` on the step. Wrap the file append in try/catch. Call `emit` once, outside the try.

### WR-03: GH_REPO is interpolated into the URL path without validation

**File:** `src/lib/githubDispatch.ts:21-23`
**Issue:** `opts.repo` goes straight into the URL path. An env typo or an odd value such as `../..` or one containing a `?` would redirect the authenticated request, with the PAT attached, to a different GitHub API path. The value is owner-controlled, so risk is low, but the token is in the header.
**Fix:** Validate with `/^[\w.-]+\/[\w.-]+$/` and fall back to the default or return `{ ok: false }` if it does not match.

## Info

### IN-01: Proxy exemption covers every future /api/cron/ route

**File:** `src/proxy.ts:19-23`
**Issue:** The prefix exemption is broader than the one route that needs it. A future route added under `/api/cron/` is unauthenticated by default unless it re-implements the bearer check.
**Fix:** Exempt only `/api/cron/scrape` explicitly, or extract a shared `assertCronAuth` helper.

### IN-02: Logout error never clears and shifts the header layout

**File:** `src/components/AccountMenu.tsx:30-45`
**Issue:** `logoutError` persists until the next logout attempt. The new wrapper div and inline span shift the header layout when it shows.
**Fix:** Clear the error on a timer or when the menu opens, or surface it via toast.

### IN-03: observeDone is inferred from any NULL-user credit_usage row

**File:** `src/db/dailyRunStatus.ts:55-60`
**Issue:** The query takes the latest NULL-user row regardless of which sport, market or outcome produced it. A manual CLI refresh or a partial refresh counts as "morning observe done" and suppresses the backup observe. The code comment acknowledges this tradeoff.
**Fix:** Acceptable as documented. Consider a dedicated marker if the backup ever skips an observe it should have run.
