<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet -> /api/cron/scrape | Public URL; anyone can send a GET. Only Vercel Cron should succeed. |
| proxy.ts -> route | Proxy cookie check is skipped for /api/cron/*; the route must authenticate itself. |
| App server -> api.github.com | Outbound call carrying the GitHub token. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05.1-01 | Spoofing | route.ts GET | mitigate | Bearer CRON_SECRET compared with node:crypto timingSafeEqual after a length check; fail closed (401) when CRON_SECRET is unset; UA/IP never trusted. Tested in route.test.ts. |
| T-05.1-02 | Denial of Service | route.ts (burning Actions minutes / Odds credits by repeated calls) | mitigate | Unauthenticated calls return 401 before any dispatch; dispatch mocked-call count asserted 0 in tests. |
| T-05.1-03 | Elevation of Privilege | proxy.ts exemption | mitigate | Exemption is startsWith("/api/cron/") only; proxy.test.ts asserts /api/other and /apix/cron still redirect. |
| T-05.1-04 | Information Disclosure | githubDispatch.ts / route.ts logs and responses | mitigate | Token only placed in the Authorization header; logs contain status code + max 200 chars of GitHub body; tests assert token/secret absent from responses and console.error args; no NEXT_PUBLIC_ names. |
| T-05.1-05 | Elevation of Privilege | GH_DISPATCH_TOKEN scope | mitigate | Documented in .env.example and the Plan 05 checkpoint: fine-grained, single repo, Actions read and write only, with expiry. |
| T-05.1-06 | Repudiation / Tampering | duplicate cron delivery | accept | Vercel may rarely deliver twice; workflow concurrency group serializes runs; worst case one extra moneyline refresh, visible in the credit meter. |
</threat_model>
