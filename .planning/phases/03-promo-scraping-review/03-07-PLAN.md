## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → confirm/dismiss actions | Untrusted promoId from any logged-in member |
| stored best_guess (scraper-derived) → activation | A stale or malformed stored guess could activate a wrong promo |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-07-01 | Spoofing / EoP | confirmPromoMatch, dismissPromo | mitigate | requireUser() first (order checked by grep); logged-out calls do no reads/writes (T-3-authz) |
| T-03-07-02 | Tampering | action input | mitigate | PromoIdInputSchema strict positive int; no user field in schema (IDOR), user id only from session |
| T-03-07-03 | Tampering (race) | concurrent reviewers | mitigate | Single conditional UPDATE ... WHERE status='pending_review' RETURNING id; 0 rows → "conflict" |
| T-03-07-04 | Spoofing (bad match) | stored best_guess | mitigate | Server re-resolves the guess against current cached odds (resolveSelection, commence > now) before writing; BestGuessSchema validates jsonb on read |
| T-03-07-05 | Repudiation | review actions | mitigate | confirmed_by_user_id / dismissed_by_user_id + reviewed_at written in the same statement (D-12) |
| T-03-07-06 | Information Disclosure | parsed promo text rendered in UI | accept | Rendered as React text nodes (auto-escaped), never dangerouslySetInnerHTML; content is the book's public promo copy |
