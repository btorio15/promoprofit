<objective>
Turn the chosen book's real promo page into validated, structured, deduplicable promo candidates. This covers the parse half of PROMO-03 and the cap-uncertainty half of PROMO-04 (D-18). Everything here is pure and fixture-tested against the logged-out capture saved in Plan 01. There is no network access and no database access.

Purpose: Plan 06 fetches the page and persists these candidates, and Plan 08 matches them to games. Because the parser is built against real markup and the owner-observed promos in 03-RECON.md, a "successful" scrape can't quietly be harvesting the wrong kind of promo (RESEARCH.md Pitfall 1).
Output: ScrapedPromo contract, fine-print parser, the target book's parser, dedupe key, and the status-after-match rule.
</objective>

// src/domain/promos/scraped.ts
export const ScrapedPromoSchema: z.ZodType<ScrapedPromo>; // superRefine rules below
export interface ScrapedPromo {
  bookKey: string; promoType: PromoType; title: string; rawText: string; sourceUrl: string;
  sportKeyHint: string | null;            // one of SPORT_KEYS when determinable, else null
  selectionText: string;                  // promoted team as shown, or "Over"/"Under"
  opponentText: string | null;            // other team as shown, when present
  teamsText: string[];                    // 1-2 team strings as shown
  marketType: PromoMarketType;
  line: number | null;                    // moneyline null; spread = promoted side's signed point; total = points
  startsAt: string | null;                // ISO, when the page shows a game time/date
  expiresAt: string | null;               // ISO, stated promo expiry
  boostPercent: string | null;            // "50.00" means +50% on profit
  boostedOddsAmerican: number | null; baseOddsAmerican: number | null;
  bonusAmount: string | null;             // 2dp string
  maxStake: string | null; maxWinnings: { amount: string; kind: WinningsCapKind } | null; minOddsAmerican: number | null;
  unparsedCapFields: CapField[];          // D-18
  finePrintNote: string | null;           // D-17, <= 160 chars
}
export interface SkippedEntry { reason: "parlay" | "sgp" | "prop" | "deposit" | "signup" | "multi_game" | "not_half_point" | "unrecognized"; text: string }
export interface ParseResult { found: number; candidates: ScrapedPromo[]; skipped: SkippedEntry[] }
export interface BookScraper { bookKey: string; url: string; render: "http" | "browser"; stealth: boolean; sourceFormat: "html" | "json"; parse(body: string, ctx: { now: Date; sourceUrl: string }): ParseResult }
// src/domain/promos/dedupe.ts
export function promoDedupeKey(p: ScrapedPromo): string; // sha256 hex
// src/domain/promos/lifecycle.ts
export function statusAfterMatch(p: { promoType: PromoType; maxStake: string | null; bonusAmount: string | null; unparsedCapFields: readonly CapField[] }):
  { status: "active"; reviewReason: null; unparsedCapFields: [] } | { status: "pending_review"; reviewReason: "caps"; unparsedCapFields: CapField[] };
// src/ingestion/promos/finePrint.ts
export type CapParse<T> = { status: "parsed"; value: T } | { status: "unparsed" } | { status: "absent" };
export function parseMaxStake(text: string): CapParse<string>;
export function parseMaxWinnings(text: string, kind: WinningsCapKind): CapParse<{ amount: string; kind: WinningsCapKind }>;
export function parseMinOdds(text: string): CapParse<number>;
export function extractFinePrintNote(text: string): string | null;
// src/ingestion/promos/books/index.ts
export const BOOK_SCRAPERS: Record<string, BookScraper>;

scraped.ts: implement the Zod schema per `<interfaces>` using z.object (strict) with a superRefine for the cross-field rules in behavior.
- Money strings match ^\d{1,6}\.\d{2}$.
- American odds are integers with |x| >= 100.
- sportKeyHint must be in SPORT_KEYS or null.
- title is at most 200 chars, rawText at most 2000, finePrintNote at most 160.

finePrint.ts: plain-text extraction only. Callers pass visible text that cheerio or JSON has already extracted, never raw HTML (RESEARCH.md Don't Hand-Roll). Use simple, linear regexes with no nested quantifiers (ReDoS guard, T-03-05-02) and case-insensitive keyword families:
- stake: max(imum)? (wager|bet|stake), "up to $X" near wager/bet
- winnings: max(imum)? (winnings|payout|profit|boost)
- min odds: min(imum)? odds, "or longer"
"Mentioned but no dollar/odds number next to it" = unparsed. Amounts are normalized to 2dp strings via decimal.js, never parseFloat. parseMaxWinnings takes the book's convention kind from the Scraper Contract; it never infers the kind from the text (D-18).

dedupe.ts: sha256 via node:crypto over bookKey | promoType | boostPercent | boostedOddsAmerican | bonusAmount | normalized rawText, where normalized means lowercase with whitespace collapsed and trimmed. The event/market match must NOT be part of the key (D-19: dedupe survives re-matching).

lifecycle.ts: statusAfterMatch as in `<interfaces>`/behavior. A boost with a null maxStake always gets "maxStake" added to unparsedCapFields, deduped, because the engine requires it (D-18).
