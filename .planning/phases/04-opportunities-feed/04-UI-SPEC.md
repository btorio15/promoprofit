## Layout & Responsive Behavior

Phone-first. Content column is the existing `max-w-[1080px]` main. Everything is designed at 360px width first.

### Top-level tabs (D-01, D-06)

- Order: **Opportunities | Bonus bets | Arbitrage | Promos | Review | Sign-up offers** (Review sits right after Promos because it is Promos' review queue; defaulted).
- `AppShell.tsx`: `ActiveTab` becomes `"opportunities" | "bonus" | "arbitrage" | "promos" | "review" | "signup"`; initial `activeTab` = `"opportunities"`. Same `TabsList variant="line"` and `keepMounted` contents.
- Six tabs do not fit 360px. The `TabsList` gets `overflow-x-auto` with `whitespace-nowrap` triggers (no wrapping, no truncation, each trigger min-h 44px). The active trigger scrolls into view on change. No new component.
- Review trigger shows a live count when the queue is non-empty: `Review (3)` with the count in `.num`. Plain text only, no colored badge (keeps accent reserved). Zero shows plain `Review`.
- Shared `OddsStatusBar` and `CreditBanner` stay above the tabs unchanged. Opportunities depends on cached odds, so `showExtendedAge` stays tied to the Arbitrage tab only.

### Opportunities panel, top to bottom

1. **Panel header:** "Opportunities" (Heading 20px) + one-line Label description (muted): "The best money available right now at your books." Matches finder/arb/promos header pattern.
2. **Profit summary** (D-05): the existing `ProfitSummary` component moved here unchanged (Total profit available, Total profit extracted, today/week/month). Defaulted: shown ONLY on Opportunities, removed from the Promos panel to avoid duplication. Available figure counts a winning pair once (D-12); this is a data rule, no visual change.
3. **Sort switch** (D-13): see below.
4. **`RiskAdvisory`** verbatim, directly above the first section (same placement rule as Phase 3: advisory sits right before the rows it warns about).
5. **Three source sections**, fixed order: **Best promos**, **Best pairs**, **Best arbs**. Pairs sit second because they are the differentiator and beat their own separate hedges by definition; defaulted.
6. Section-level empty state and a whole-screen empty state (see Empty states).

Sections are built from a `sources` array (D-02) so a future source (Kalshi/Polymarket) adds one entry and one component with no layout rework. Each section = `SectionHeader` + up to 5 rows in a `flex flex-col gap-3` stack.

### Section header

- Row: Heading 20px title on the left, optional "See all" link on the right (`Button variant="link"`, Label 14px, min-h 44px hit area via padding; defaulted: switches the active tab in place via a callback from `AppShell`, not a URL nav).
- "See all promos" (Best promos) switches to Promos. "See all arbs" (Best arbs) switches to Arbitrage. **Best pairs has no See all** (pairs exist only here).
- Under the title, Label muted count/caption: "Top 5 by guaranteed profit" or "Top 5 by ROI" (follows the sort switch).

### Sort switch (D-13, D-14, D-15)

- Component: existing `ToggleGroup` (single-select, `type` single, cannot deselect) with two items: **Profit ($)** and **ROI %**. Each item min-h 44px, min-w 44px, `px-4`. Label 14px.
- Selected item uses the accent chip style (already reserved for "active chip in single-select toggle group").
- Placed under the profit summary, left-aligned, with a Label prefix "Sort by". Same control and copy on Promos, placed in the Promos header area above the active list.
- Changing it re-picks the top 5 in every section immediately (client-side re-rank from the same payload; no spinner, no refetch).
- Persisted per device in localStorage under one key shared by both screens' switches, in a try/catch wrapper that falls back to Profit ($) (follows `FinderForm.tsx` pattern). Both screens stay in sync via a single lifted state in `AppShell` (defaulted).
- Bonus-bet promos have conversion % instead of ROI. When sorted by "ROI %", the measure for a bonus-bet row is its conversion % (same slot the Phase 3 row already uses). Caption on the row stays "Conversion".

### Promo rows (Best promos section)

Reuse `PromoRow.tsx` verbatim (six-column grid on desktop, stacked on mobile, whole-row `Collapsible` trigger at 44px). Differences: no "other book" dimming (D-16 excludes them), no Mark-done change. All existing badges, Mark used/done button and expanded panel behavior carry over.

### Arb rows (Best arbs section)

Reuse `ArbRow.tsx` verbatim inside the same section shell. Both books are the member's (D-18); no visual change.

### Pair card (Best pairs section, D-07..D-10) - new component `PairCard`

A single `Collapsible` card (`rounded-lg border border-border bg-secondary`), whole header row is the trigger (min-h 44px), same chevron and expand idiom as `PromoRow`.

Collapsed (mobile stack, `flex flex-col gap-3 p-4`):

1. **Caption line** (Label, muted): `{sport} · {kickoff}` then market badge (`Badge variant="outline"`, e.g. "Moneyline", "Spread +3.5", "Total O/U 44.5") then pair-type badge `Badge variant="outline"`: **Boost + Boost** or **Boost + Bonus bet**.
2. **Two leg lines** stacked (`gap-2`), each Body 16px: `{Book} {promo-type badge}: {side} {odds} - stake {formatUsd}`. Odds and stake in `.num`. A subtle `border-l-2 border-border pl-3` on each leg separates the two legs visually (no color coding, so accent stays reserved).
3. **Result line:** Guaranteed profit `.num text-xl font-semibold text-primary` (Heading 20px), ROI caption "ROI" with `formatPct` beside it in Label.
4. **Comparison line** (D-07, always visible, Label 14px muted): `vs. {$X} + {$Y} hedging each separately` with both amounts in `.num`, followed by a positive delta phrase `+{$Z} more together` (Label, `.num` on the amount, text-foreground weight 400; not accent).

Desktop (>= md): a two-row layout inside the same card: row 1 caption; row 2 a grid `grid-cols-[minmax(0,1.4fr)_minmax(0,1.4fr)_120px_96px_20px]` = Leg A | Leg B | Guaranteed profit | ROI | chevron; comparison line spans the card beneath. Leg cells match the Hedge column typography from `PromoRow`.

Expanded panel (`p-6`, same border-t as `PromoDetails`): reuses `PromoDetails` layout twice-over conceptually: Display-size (36px) profit restatement, numbered steps "1. Bet {stake} at {Book} on {side} at {odds}" and "2. Bet {stake} at {Book} on {side} at {odds}", per-outcome payout table (both outcomes must show the same profit), any cap notes per leg using the Phase 3 cap-bound wording ("Capped at {book}'s {$X} max stake ..."), a bonus-bet note for a bonus leg ("Bonus bet stake isn't returned"), and the **Mark done** button (below).

Pair card never shows "Same book" (pairs require two different books by nature). "Tie risk" badge is reused on a leg when applicable.

### Mark done on a pair (D-11)

- Reuse `MarkUsedButton` behavior/styling; label **Mark pair done** (defaulted so the user knows it closes both promos).
- Tap opens the same confirm pattern already used for single Mark done (no new dialog type). Confirm copy below.
- On success: both promos disappear from Opportunities and move to Promos' Done list as one entry (a `DonePairRow` variant of `DonePromoRow` showing both legs and the paired profit once); Total profit extracted increases by the pair profit once; Undo affordance is the same as single Done.
- "Odds changed" rejection (260929-igk rules): if the server rejects because odds moved, the card shows an inline `Alert` (destructive-tone matches existing single-row behavior) with the copy below and the row re-ranks from fresh data. No optimistic removal before server success.

### Book filtering surfaces (D-16..D-19)

No new UI element. Opportunities silently omits anything involving a book the member does not have. Its section empty states explain this and link to `/settings` ("Manage your books"). Promos keeps dimmed/last rule unchanged.

### Review tab (D-06)

- Contains, in order: panel header **"Review"** + Label description, then existing `ScrapeStatusPanel`, then existing `ReviewQueueSection` ("Needs review (N)" and "Needs a look"). Components move as-is; their contracts are 03-UI-SPEC's.
- Because the "Needs review" section is entirely absent when empty (Phase 3 rule), Review needs its own empty state (below) when the queue is empty and nothing needs a look. Scrape status lines are always shown.
- Promos panel after the move: header, sort switch, `RiskAdvisory`, active list, Done list. No review queue, no scrape status, no profit summary.

### Loading, staleness, and odds-changed

- **Loading:** three skeleton section shells (existing `skeleton.tsx`: a 20px-high title bar plus three 88px-high row blocks per section). Profit summary skeleton is one block matching its height. No spinners.
- **Odds age:** the shared `OddsStatusBar` already shows age. Opportunities adds no per-row age. When odds are stale (status bar's existing stale state), a one-line Label warning (`text-warning`, `TriangleAlert` size-4) sits under the panel description: "Odds are more than {N} hours old, so these numbers may have moved." (defaulted; reuses amber, no new token).
- **Pair/promo row recompute after Refresh:** `recomputeKey` from `AppShell` refetches Opportunities like the other tabs.

### Touch targets & dark mode

44px minimum for tab triggers, sort items, row triggers, See all, Mark pair done. (Phase 3's 40px `h-10` allowance is not reused here: everything new on this phase is a primary phone interaction, so targets are 44px.) Dark mode: OS `prefers-color-scheme` only, unchanged.

### Empty states

All reuse the `EmptyState` shell (`rounded-lg border border-dashed border-border bg-background p-6`, Heading + Body + optional CTA). Section-level empties are compact (`p-4`, Body + Label only, no Heading) so they do not dominate the screen.

Whole-screen (replaces all three sections, profit summary still shown):
1. **No odds cached yet:** heading "No odds cached yet", body "Press Refresh odds to pull current Colorado odds before opportunities can show up." (reuses existing pattern.)
2. **No books selected / nothing at your books:** heading "Nothing at your books right now", body "None of the current promos or arbitrage bets can be placed at the sportsbooks you've selected. Add more books to see more opportunities." + CTA `Button variant="outline"` -> `/settings`: "Manage your books".
3. **No promos scraped yet:** reuse Phase 3 copy "No promos scraped yet" (only when sections 2 and 3 of Phase 3 empties would apply and arbs are also empty).

Per-section (when only that section is empty):
- Best promos: "No promo hedges right now."
- Best pairs: "No pairs right now. A pair only shows up when two promos on opposite sides beat hedging each one separately."
- Best arbs: "No arbitrage bets at your books right now."

Review tab empty (queue empty and nothing needs a look): compact block under the status panel, "Nothing to review. New scraped promos that need a human look will show up here."

## Color

Unchanged palette; reserved-for lists extended only where noted.

| Role | Light | Dark | Usage |
|------|-------|------|-------|
| Dominant (60%) | `#FFFFFF` | `#09090B` | Page background |
| Secondary (30%) | `#FAFAFA`, border `#E4E4E7` | `#18181B`, border `#27272A` | Pair cards, rows, summary, empty-state contrast |
| Accent (10%) | `#059669` | `#10B981` | See list |
| Destructive | `#DC2626` | `#EF4444` | See list |
| Warning | `#D97706` | `#F59E0B` | Stale-odds line only |

**Accent reserved for (exhaustive; nothing else):**
1. Primary CTA fills (unchanged)
2. Guaranteed-profit figure in every row on every tab, including pair cards (collapsed and expanded), and the profit-summary headline figures (unchanged from 260927-n12)
3. The selected item of the profit/ROI sort switch (existing "active chip" rule)
4. Checked checkbox fills, focus rings, book-picker checks (unchanged)
5. **Mark pair done** confirm button (same family as single Mark done confirm)

**Destructive reserved for:** validation errors, refresh/search failures, and the odds-changed rejection alert on a row. No new destructive buttons this phase (nothing is irreversible: Mark done has Undo).

Explicitly NOT accent: section titles, "See all", pair-type/market badges, the comparison "+$Z more together" delta, tab Review count, leg separators.

## Open questions for owner

None block planning; each has a default already used above.

1. **Where does the Review tab sit?** Default: right after Promos, with a plain-text count "Review (3)" when something needs attention. Alternative: last, after Sign-up offers.
2. **Should the profit summary stay on Promos too?** Default: no, Opportunities only (avoids showing the same big numbers twice on adjacent tabs).
3. **"See all" links:** Default: included on Best promos and Best arbs, switching tabs in place. Alternative: omit.
4. **When sorted by ROI %, bonus-bet promos rank by their conversion %.** Default: yes. This mixes two percentages in one ordering; confirm the owner is fine with it (alternative: rank bonus bets after boosts, or hide them under ROI sort).
5. **Six tabs on a phone scroll sideways.** Default: horizontal scroll. Alternative: shorten labels (for example "Bonus", "Arbs") or move Sign-up offers into the account menu.
