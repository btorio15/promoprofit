### CR-01: Whole-dollar arb solver misses the optimal stake split and hides real arbs

**Files modified:** `src/domain/hedge/arbMath.ts`, `src/domain/hedge/arbMath.test.ts`, `src/app/actions/find-arbs.test.ts`
**Commit:** ddeea00
**Status:** fixed: requires human verification (logic change to money math)
**Applied fix:** The old solver tried only four candidates (floor/ceil of the full-total split). It now searches exactly, still using decimal.js only:
- It checks every total-laid value L, in precision units, from the cap downward.
- For each L, the discrete crossing of `floor_c(a*Da)` (strictly increasing) and `floor_c((L-a)*Db)` (strictly decreasing) provably lies within ±2 units of the balance point `a* = L*pA/sum`. The solver checks that window plus the legal endpoints.
- The scan stops once the upper bound `L/sum - L` falls below the best profit so far, or below $0.01 when nothing positive has been found yet.
- Tie-break is unchanged: more profit, then less laid, then smaller stakeA.
- The bound and `a*` use the 40-digit implied sum, not the 20dp display value. Rounding the sum could nudge an exactly-tight bound under the threshold, and the brute-force cross-check caught this.

Performance: a $100k total runs in 0–31 ms per pair in both precisions.

New tests:
- A table of the reviewer's counterexamples: -150/+200 @ $10 → 5/3 for $0.33, -250/+400 @ $7 → 3/1 for $0.20, -250/+300 @ $25 → 17/6 for $0.80, -300/+400 @ $50 → 37/10 for $2.33.
- An exhaustive brute-force cross-check with its own independent reference implementation:
  - Whole dollars: 16 odds pairs × totals $1–$60.
  - Cents: 16 pairs × $0.50 / $1.37 / $2.49 / $3.33.

**Changed fixtures** (each marked with a `CR-01 (01.1 review fix)` comment in the test):

### WR-01: A mid-loop refresh failure hides every sport not yet refreshed

**Files modified:** `src/ingestion/odds/store.ts`, `src/ingestion/odds/refresh.ts`, `src/ingestion/odds/refreshExtended.ts`, `src/ingestion/odds/refreshExtended.test.ts`, `src/app/actions/refresh-odds.test.ts`, `src/app/actions/refresh-spreads-totals.test.ts`, `src/components/arb/ArbForm.tsx`, `src/components/finder/OddsStatusBar.tsx`, `src/db/schema.ts`, `src/db/queries.ts`
**Commit:** b62ea67
**Applied fix:**
- **Buffer, then commit once.** Both refresh paths now fetch every sport into memory first, recording quota after each fetch as before. Only after the loop succeeds do they call one store function:
  - `commitOddsRefresh` does the cached_odds delete+insert for each sport, then both purges.
  - `commitSpreadsTotalsRefresh` writes the extended rows, the h2h projection into cached_odds, and all four purges.
  - Each runs as a single neon-http `db.batch([...])`, which is one Postgres transaction. A failed fetch or a failed commit therefore leaves both caches unchanged, and the two caches can no longer diverge.
- **Store cleanup.** The old per-sport `replace*` and `purge*` exports were replaced by these two commit functions. The only external callers were the refresh modules.
- **Tests.** The mid-loop tests in both paths now assert that neither commit function is called. Added a commit-failure test for the extended path: credits are still recorded and the error is key-free.
- **UI.** `ArbForm.handleSearchOutcome` now calls `router.refresh()` on `error`/`busy`, and `OddsStatusBar` does the same on `error`, so the credit meter reflects credits spent before a failure.
- **Comments.** The `schema.ts` D-16 comment (which overlaps IN-05) and the `getCachedEvents` comment were updated to describe the h2h projection and the all-or-nothing commit.
