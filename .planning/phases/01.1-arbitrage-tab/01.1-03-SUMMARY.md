## Decisions Made

- Guarded the `bonusAmount`/`maxHedgeAmount` Zod refines against non-numeric input (`!PATTERN.test(value) || new Decimal(value)...`) instead of an unconditional `new Decimal(value)` call, because zod v4 runs every chained check on a field regardless of earlier failures — an unconditional refine threw an uncaught `DecimalError` on inputs like `"abc"` instead of producing a clean field error. This is a pre-existing latent bug in `bonusAmount` (never triggered by prior tests, which only exercised `"0"`); fixed both fields together since they share the exact pattern in the same file (Rule 1 — bug fix, in-scope file).
- `limitExcludedAll[scope]` only re-ranks without the cap when the capped ranking for that scope is empty (never unconditionally), keeping the extra computation pure in-memory and zero-cost when a cap isn't set or a scope already has results.
- Kept the "Max hedge amount" input fully controlled by `usePersistentString` rather than registering it with react-hook-form, since its visibility/validation is gated by a separate checkbox not modeled in `FinderInputSchema`'s always-required shape; server `fieldErrors.maxHedgeAmount` is routed to the same local error state instead of `form.setError`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Guarded refine to prevent a crash on non-numeric money-input values**
- **Found during:** Task 1, running the new `find-hedges.test.ts` "rejects invalid maxHedgeAmount values" case with `"abc"`
- **Issue:** `new Decimal(value)` inside `.refine()` throws `DecimalError: Invalid argument` when `value` doesn't match the regex pattern, because zod v4 runs every chained `.regex()`/`.refine()` check independently rather than short-circuiting after the first failure — an uncaught throw instead of a field-error response.
- **Fix:** Changed both `bonusAmount` and `maxHedgeAmount` refines to `(value) => !PATTERN.test(value) || new Decimal(value)...`, skipping the Decimal construction whenever the regex already failed.
- **Files modified:** `src/domain/finder/finderInput.ts`
- **Verification:** `npx vitest run src/app/actions/find-hedges.test.ts` passes the `"abc"`/`"1.234"`/`"-5"`/`"0"` cases without throwing; full suite green.
- **Committed in:** `defe2a7` (Task 1 GREEN commit)
