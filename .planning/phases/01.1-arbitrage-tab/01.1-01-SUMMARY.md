# Phase 01.1 Plan 01: Arbitrage Domain Math Summary

**Pure, fixture-tested arb domain layer: two-leg stake-split solver, joint book-pair search with exact-tie detection, and a half-point exact-line matcher for spreads/totals — all decimal.js, zero I/O, cent-exact.**

## Performance

- **Duration:** ~25 min
- **Tasks:** 3 completed
- **Files modified:** 7 (6 created, 1 modified)

## Accomplishments
- `calculateArb` (src/domain/hedge/arbMath.ts) computes cent-exact stakes/payouts/profit for a two-leg arb, enforcing the strict `impliedSum < 1` threshold (no epsilon, no minimum-return filter per D-04/D-05) and never laying more than the user's entered total stake (D-01), with a worst-case-maximizing rounding rule for both whole-dollar and exact-cents modes (D-02). All 6 fixtures from the plan's Behavior section — including two repeating-decimal (-300/-275) cases where the naive independent-rounding pair would exceed the stake cap — pass with exact-to-the-cent expected values.
- `findBestArbPair`/`rankArbs` (src/domain/hedge/rankArbs.ts) do an explicit O(n²) cross-book search rather than reusing the finder's per-side "independent best price" pattern, correctly handling the case where the same book has the best price on both sides (D-06) and listing only exact-price ties as "tied books" (D-07). `moneylineToArbMarket` adapts the existing `TwoWayMoneylineMarket` into the new shared `ArbMarket` contract that both the moneyline and spreads/totals pipelines emit. Results sort by return % descending, then commenceTime ascending, then rowKey ascending, with no result limit (D-11).
- `extractTwoWaySpreadsAndTotals`/`isHalfPoint` (src/domain/hedge/spreadsTotalsFilter.ts) extract half-point spread/total lines exactly matched across books (D-08), grouping spreads by the home team's *signed* point (not magnitude) so a flipped favorite never gets mispaired, and excluding whole-number lines entirely (push risk). `OddsOutcomeSchema` gained an additive `point: z.number().optional()` field so this filter has a typed accessor instead of relying on `looseObject`'s untyped passthrough.

## Decisions Made
- Tightened RESEARCH.md's independent-rounding sketch: `calculateArb` treats the entered total stake as a hard cap, rejecting any rounded candidate pair whose sum exceeds it, rather than allowing a slightly-over-budget pair to be selected.
- Rounding tiebreak (Claude's discretion per CONTEXT.md): maximize `guaranteedProfit`, then minimize `totalLaid`, then minimize `stakeA` — protects the worst-case floor first, then risks the least money.
- `findBestArbPair` uses alphabetical bookKey tiebreaking (sideA first, then sideB) on exact implied-sum ties, for deterministic test/production behavior.
