## Layout & Responsive Behavior

(Not in the base template — added because this phase changes the page shell from a single finder screen to a two-tab app.)

- **Page shell (new):** `OddsStatusBar` (sticky, shared) → `Separator` → `CreditBanner` (shared) → top-level `Tabs` ("Bonus bets" | "Arbitrage", D-09) → the active tab's panel. The status bar, credit banner, and page header sit *above* the tabs so age/credits/refresh are visible regardless of which tab is open. Use the existing `src/components/ui/tabs.tsx` `Tabs`/`TabsList`/`TabsTrigger`/`TabsContent` (already used for sport sub-tabs) — no new tab component. `TabsList variant="line"` at the top level, same visual treatment as the sport sub-tabs one level down, so the two tab rows are visually distinguishable only by position/hierarchy (top-level tabs sit directly under the status bar with more top margin; sport sub-tabs sit inside each panel, closer to their rows).
- **Bonus bets tab panel:** unchanged Phase 1 `FinderForm` + `ResultsList`, plus the new max-hedge checkbox (below).
- **Arbitrage tab panel, top to bottom:**
  1. Panel header: `h1`-equivalent "Arbitrage" (Heading, 20px) + one-line description, matching the finder header's pattern.
  2. A `Card` (matches the finder form card: `p-6`) containing, in one row on desktop (`flex flex-wrap items-end gap-4`, stacked full-width on mobile):
     - **Total stake** `Input` (money, `.num`, required)
     - **Stake precision** `ToggleGroup` (two options: "Whole dollars" / "Exact cents", single-select, default "Whole dollars" per D-02)
     - **Search spreads & totals** `Button` (outline variant, right-aligned on desktop, full-width on mobile) — this is the only user-initiated fetch on this tab; moneyline arbs render automatically from whatever odds are already cached, with no submit step.
  3. **Account-risk advisory** (`Alert`, neutral/secondary tone, not warning/destructive) sits directly under that card, above the results — always visible without scrolling on both mobile and desktop, so it's read before the user acts on a row. See Copywriting Contract.
  4. **Second odds-age line** ("Spreads & totals updated…") — lives in the sticky `OddsStatusBar` as an additional line, but is **only rendered while the Arbitrage tab is active** (the Bonus bets tab never needs spreads/totals freshness). This keeps "prominent" (roadmap success criterion 3) satisfied via the sticky bar rather than duplicating age text lower on the page. Claude's discretion — defaulted: the moneyline age line already in the status bar is reused as-is (it applies to both tabs, since arbs also depend on moneyline freshness); only the second line is new and tab-conditional.
  5. Sport sub-tabs with counts: All · NFL · NCAAF · MLB · NBA · NCAAB — identical component and order to `ResultsList.tsx`'s existing `TAB_KEYS`/`SPORTS` pattern (D-12). Reused unchanged, not re-decided.
  6. Ranked arb rows (D-11: sorted by return %, highest first), same compact-row / expand-to-`Collapsible` pattern as the finder (D-10), same desktop grid template (`minmax(0,1.3fr) minmax(0,1fr) minmax(0,1.2fr) 120px 96px 20px`) reused verbatim from `ResultRow.tsx` — six columns: Game & time (+ market badge) | Side A book+odds | Side B book+odds | Guaranteed profit | Return % | chevron. Mobile stacks identically to the finder's stacked micro-layout.
- **Row content differences from the finder** (both legs are cash, not one bonus + one hedge):
  - Column labels change from "Bonus side / Hedge side" to **"Side A / Side B"** (mobile `mlabel` caption text).
  - No "Same book" badge is possible on this tab (D-06: legs are always different books) — omit that badge entirely from arb rows.
  - "Tie risk" badge (NFL 2-way moneyline) reuses the finder's identical badge/tooltip, unchanged, since the same market rule applies.
  - **Market badge** ("Moneyline" / "Spread ±X.5" / "Total O/U X.5", D-15) sits inline after the sport/kickoff caption in the Game cell, e.g. "NFL · Sun 11:00 AM · `Spread +3.5`" — same `Badge variant="outline"` component as "Same book"/"Tie risk", just relocated to the Game cell since it describes the row's market, not either side.
  - **"Multiple books" badge** (D-07) sits next to whichever side's price is tied by other books, in the same position "Same book" occupies in the finder row. Clicking/tapping it opens a `Popover` (new — not yet in the repo, shadcn official) listing the tied books, e.g. "Also at: FanDuel, BetMGM." Use `Popover`, not `Tooltip`, because the list must be reachable by tap on mobile (Tooltip's hover-first pattern doesn't work there); the finder's existing `Tooltip` pattern is reserved for the static one-line explanations ("Same book" — n/a here, "Tie risk").
- **Expanded row panel:** same two-column desktop / stacked-mobile `panel` layout as the finder (Display-size profit restatement, numbered steps list, per-outcome payout table). New for arbs:
  - When stake precision is "Whole dollars" and the two outcomes' net profit differ by a cent or more (rounding artifact), the Display-size headline shows the **lower** of the two (D-02, "the headline shows the lower one"), labeled "Guaranteed profit (worst case)" instead of plain "Guaranteed profit." The per-outcome table still shows both exact net-profit values so the user can see the small spread.
  - When precision is "Exact cents," both outcomes are identical to the cent (same as the finder today) and the headline reads plain "Guaranteed profit," unchanged wording.
  - Steps list references **"Leg A" / "Leg B"** (not a bonus/hedge distinction), each naming its own book: "Bet $X at {Book A} on {Side A} {odds}" / "Bet $Y at {Book B} on {Side B} {odds}."
- **Max hedge amount (folded todo, D-17…D-19, Bonus bets tab only):** a `Checkbox` (new — not yet in the repo, shadcn official) labeled "Limit hedge amount" sits directly under the Bonus amount field, collapsed/unchecked by default so the form stays uncluttered (owner's stated reason). Checking it reveals a "Max hedge amount" `Input`, styled identically to the Bonus amount field (money, `.num`, same height/validation idiom). Value and checkbox state persist via `localStorage` (D-03/D-19), not the DB.
- **Persistence (D-03):** total stake, precision toggle, and max-hedge amount are all `localStorage`-only, scoped to the browser — no new server round trip or loading state is needed for these three controls; they hydrate on mount and update instantly on change, same as any other pure client input.
- **Touch targets:** unchanged from Phase 1 — all inputs/buttons/toggles ≥40px height, full mobile row tap target ≥44px, including the new "Search spreads & totals" button and the "Limit hedge amount" checkbox's tap area (label + box together, ≥40px).
- **Dark mode:** unchanged — OS `prefers-color-scheme` only, no manual toggle, no new work required for this phase.

## Color

Unchanged palette from Phase 1 — same hex/oklch values, same light/dark pairs. The reserved-for list below is **extended** (not replaced) to cover this phase's new accent-bearing elements; nothing outside this list may use accent color.

| Role | Value (light) | Value (dark) | Usage |
|------|------|------|-------|
| Dominant (60%) | `#FFFFFF` | `#09090B` (zinc-950) | Page background |
| Secondary (30%) | `#FAFAFA`, border `#E4E4E7` | `#18181B`, border `#27272A` | Status bar, cards, result rows (both tabs), expanded-panel surface, table zebra rows, popover surface |
| Accent (10%) | `#059669` (emerald-600) | `#10B981` (emerald-500) | See "Accent reserved for" below |
| Destructive | `#DC2626` (red-600) | `#EF4444` (red-500) | Refresh/search blocked state, refresh/search failure alerts, inline field validation errors |
| Warning (amber) | `#D97706` (amber-600) | `#F59E0B` (amber-500) | Stale moneyline odds age (>2h), stale spreads/totals age (>2h, same threshold), credit-meter warning banner (<100 credits) |

**Accent reserved for (exhaustive — extends Phase 1's list with items 3b and 4; nothing else may use accent):**
1. "Find hedges" primary CTA fill (Bonus bets tab, unchanged from Phase 1)
2. The guaranteed-profit dollar figure in every result row on **both** tabs — collapsed Heading-size, and expanded Display-size restatement (including the whole-dollar "worst case" variant)
3. The active/selected chip in any single-select toggle group: the sport-filter/sport-sub-tab chips (unchanged), **and (new, 3b) the active chip in the stake-precision toggle** ("Whole dollars" / "Exact cents")
4. **(new)** The checked-state fill of the "Limit hedge amount" checkbox (finder) — standard shadcn primary-checkbox styling, same meaning family as focus rings/active chips (this control is "on")
5. Input focus ring (`focus-visible` outline) on all form controls, both tabs

**Explicitly NOT accent (Claude's discretion — defaulted, consistent with Phase 1's "Refresh odds is outline, not accent" precedent):** the "Search spreads & totals" button is an **outline/secondary** button, not accent-filled. It is an infrequent, explicit, credit-costing utility action — like "Refresh odds" — not the page's primary conversion moment (there is no primary conversion moment on the Arbitrage tab; the arb rows and their profit figures are). Giving it accent would visually compete with the profit figures for attention on a screen whose entire point is the profit column.

The account-risk advisory uses **secondary surface + default foreground** (a plain `Alert` with no `variant`, i.e. neither `warning` nor `destructive`) — it is a standing disclosure, not a time-sensitive or error condition, so it must not borrow amber or red's "something needs attention now" meaning. Claude's discretion — defaulted.
