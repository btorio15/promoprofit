# Phase 01.1 Plan 04: Extended (Spreads/Totals) Refresh Orchestration Summary

**Guarded, always-confirmed `runSpreadsTotalsRefresh` server-side orchestration that fetches h2h+spreads+totals at ~3x credits into an independent cache table, sharing the normal refresh's lock/ledger/gate but never its purge lifecycle.**

## Performance

- **Duration:** ~20 min
- **Tasks:** 3 completed, each as a RED (test) -> GREEN (feat) TDD pair
- **Files modified:** 11 (4 created, 7 modified)

## Accomplishments

- `fetchSportOdds` (src/ingestion/odds/client.ts) gained an optional `markets?: readonly string[]` option defaulting to `["h2h"]`, so the existing normal-refresh call site is byte-for-byte unchanged (SC1: moneyline arbs cost zero extra credits) while the new extended path can request `markets=h2h,spreads,totals`. `estimateRefreshCredits` (quota.ts) gained a `marketCount: number = 1` third parameter, scaling cost by market count (`estimateRefreshCredits(4, 7, 3) === 12 === 3 * estimateRefreshCredits(4, 7)`); the existing 2-arg call sites and their tests stayed valid unmodified.
- `runSpreadsTotalsRefresh` (src/ingestion/odds/refreshExtended.ts, new) is a structural mirror of `runOddsRefresh`'s lock-acquire -> credit-gate -> fetch-loop -> finally-credit-record skeleton (same `refresh_lock` row id=1, same `credit_usage` ledger, same `evaluateRefreshGate` thresholds), but every unconfirmed call unconditionally returns `confirm_required` with a real ~3x estimate -- even outside the shared 15-minute confirm window -- so the UI's confirm dialog always shows the true cost before any credits are spent (D-14). On a confirmed run it fetches `EXTENDED_MARKETS = ["h2h","spreads","totals"]` per in-season sport, writes the raw events to `cached_extended_odds` via `replaceExtendedSportOdds` (Plan 02) AND a pure h2h-only projection (`toH2hOnlyEvents`) to `cached_odds` via the existing `replaceSportOdds`, then purges both tables -- extended-table purges first, then the normal-cache purges -- only after the entire fetch loop succeeds. A mid-loop failure purges nothing and still records the actually-spent credits (WR-02 discipline preserved).
- `refreshSpreadsTotals` server action (src/app/actions/refresh-spreads-totals.ts, new) is a structural copy of `refreshOdds`, validating `{ confirmed: boolean }` with the same Zod shape and revalidating `"/"` only on `status: "ok"`.
- `getOddsStatus` (status.ts) gained `extendedOddsFetchedAt` (null when `cached_extended_odds` is empty, else an ISO string via `getExtendedOddsFreshness`) and `estimatedExtendedRefreshCredits` (derived from the latest credit row's `sportsFetched` count with `marketCount: 3` when known, else the `SPORT_KEYS.length` upper bound -- never a hardcoded literal).
- `scripts/odds-smoke.ts` gained an `--extended` flag (parsed anywhere in argv, sport key taken as the first non-flag argument) that fetches `h2h,spreads,totals` against only the 7 free-tier books, reports how many bookmakers returned each of spreads/totals and how many of those had a half-point line (reusing Plan 01's `isHalfPoint` rather than re-implementing it), and exits 1 if events exist but no bookmaker returned a usable half-point spread/total line. The non-extended ODDS-05 mode is unchanged. This script was not run live in this plan (that happens in Plan 08).

## Decisions Made

- The extended refresh's h2h projection into `cached_odds` (documented in `refreshExtended.ts`'s file header as an explicit discretion choice) means a single "Search spreads & totals" press also refreshes the moneyline tab's data with the same timestamp -- the user already paid for the h2h market as part of the 3x request, so both tabs benefit from one fetch. WR-01 (every in-season sport rewritten before any purge) and D-16 (normal refresh never purges the extended table; `refresh.ts` never imports from `refreshExtended.ts`) both hold, verified by grep gates and a dedicated test.
- `estimatedExtendedRefreshCredits` re-derives from `latest.sportsFetched` with `marketCount: 3` rather than reusing `latest.refreshCost`, because the shared `credit_usage` ledger's most recent row may have been written by either the normal or the extended refresh -- reusing its raw cost verbatim would sometimes show a 1x cost as the "extended" estimate.

## Issues Encountered

- Two of my own test fixtures in `refreshExtended.test.ts` initially set `now` to the 1st of a month with a `recordedAt` 24 hours earlier (crossing into the previous billing month), which unintentionally triggered `effectiveRemaining`'s CR-01 "unknown balance" behavior and caused three `blocked` tests to proceed to the fetch loop instead of blocking. Fixed by moving `now` to the 15th of the month in those three tests (matching `refresh-odds.test.ts`'s existing convention) — no production code was at fault; confirmed by re-running RED before the fix and GREEN after.
