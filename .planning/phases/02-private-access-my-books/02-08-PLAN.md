<objective>
Close verification gap 2 (CR-02 BLOCKER + WR-01): / redirects to onboarding when usable-and-saved books are empty, but /onboarding/books redirects back to / when the RAW saved-key list is non-empty — an infinite loop for a user whose saved books all lost usability. /settings is also dead in that state because it seeds the form with unrenderable stale keys, so every save fails the allowlist.

Fix: introduce one shared predicate, getUsableUserBooks(userId), in src/db/queries.ts and make all three pages use it. / and /onboarding/books then redirect on complementary conditions of the same value (no loop possible), and Settings seeds initialKeys from it (stale keys dropped, so Save works).

Purpose: DASH-02 — the user can always reach and fix their book selection.
Output: getUsableUserBooks + unit tests; three pages switched to it; a routing invariant test.
