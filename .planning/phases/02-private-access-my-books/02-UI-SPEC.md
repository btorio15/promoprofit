# Phase 2 — UI Design Contract

> Visual and interaction contract for Private Access & My Books. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Non-interactive research run:** `02-CONTEXT.md` already locks every scope, flow, and copy-tone decision for this phase (D-01…D-23) or explicitly delegates the remainder to "Claude's Discretion" (password rules, rate limiting, invite token format, route-protection mechanism, logged-out redirect, exact copy). The design-system tokens (shadcn preset, palette, spacing, typography) are **unchanged from Phase 1/01.1** per the CONTEXT.md canonical-refs instruction — this phase adds new *screens* (login, invite redemption, book picker, settings, header account menu) on top of the existing system, it does not introduce a new one. Items marked **"Claude's discretion — defaulted"** below are the presentation choices CONTEXT.md left open, resolved using the established Phase 1/01.1 idiom rather than inventing new patterns. No interactive channel was available in this session (CONTEXT.md left nothing design-relevant unanswered), consistent with how 01.1's UI-SPEC was produced.

## Layout & Responsive Behavior

(Not in the base template — added because this phase introduces five new screens/states and a new persistent header, none of which existed in Phase 1/01.1.)

### App-wide: new header (D-11)

- **`AppHeader`** (new, custom composition — not a single shadcn block): a slim row that now sits **above** `OddsStatusBar` inside the authenticated shell (`AppShell.tsx`). Secondary surface (`bg-secondary`), `border-b`, `px-4`, height `h-14` (56px), content constrained to the same `max-w-[1080px]` container as the rest of the app, `flex items-center justify-between`.
  - Left: app name **"PromoProfit"** (Heading, 20px/600) — plain text, not a link (there is no other page to navigate "home" to in this phase).
  - Right: **`AccountMenu`** trigger — a `Button variant="ghost"` (h-10, min 40px touch target) showing the user's display name (Label, 14px) + a `ChevronDown` icon (lucide, `size-4`).
  - **Claude's discretion — defaulted:** `AppHeader` is **not sticky** (unlike `OddsStatusBar`, which keeps its existing `sticky top-0 z-40`). It scrolls away with the page; only the odds status bar needs to stay pinned while scanning long result lists. This avoids stacking two sticky elements and consuming extra vertical space on mobile, and requires no change to `OddsStatusBar`'s existing sticky CSS.
- **`AccountMenu`** (new, `dropdown-menu` shadcn block): opens below the trigger, right-aligned. Two items only: **Settings** (navigates to `/settings`) and **Log out** (calls the logout action, redirects to `/login`). Both items default menu-item styling (no destructive-red on Log out — see Color section for rationale). No avatar/profile image anywhere in this phase (no image upload, no email-derived avatar service — out of scope); the display-name text is the only identity affordance.

### Login page (`/login`)

- Unauthenticated route — renders **without** `AppHeader` or `OddsStatusBar` (no session, nothing to show odds/credits for). Full-viewport, dominant-surface background, content vertically and horizontally centered.
- Structure, top to bottom, inside a centered column (`max-w-[400px]`, `mx-auto`, `px-4`):
  1. **"PromoProfit"** (Heading, 20px/600), centered.
  2. One-line tagline (Label, 14px, muted-foreground), centered: "Private access for invited friends."
  3. A `Card` (`p-6`) containing the login `form`: Email `Input` (type `email`), Password `Input` (type `password`), inline field errors below each, then the primary CTA `Button` (full width, accent, `h-10`): **"Log in"**.
  4. Below the card, small centered `Label`-size muted text: "No account? Ask the person who invited you for a link." — no signup link exists (D-01); this line only explains, it does not route anywhere.
- **Claude's discretion — defaulted:** no "forgot password" link or self-serve flow rendered anywhere on this screen — D-07 makes password reset owner-script-only with no in-app entry point, so the page must not imply one exists.
- Mobile and desktop are visually identical (single centered column at both widths) — this page never needs a wide layout.

### Invite redemption page (`/invite/[token]`)

Two mutually exclusive states, same centered-column shell as `/login` (no `AppHeader`/`OddsStatusBar`):

- **Valid, unused, unexpired token:** `Card` (`p-6`) titled **"Join PromoProfit"** (Heading), one-line body (Label, muted): "Create your account to get started." Form fields, in order: Display name `Input`, Email `Input`, Password `Input` (D-04), each with inline validation errors. Primary CTA (full width, accent, `h-10`): **"Create account"**. On success, redirects straight into the book-picker step (D-08) — no separate "account created" confirmation screen.
- **Invalid / already-used / expired token:** `Card` (`p-6`) with no form — heading **"This invite is no longer valid"** (Heading), body (Body, 16px): "This link has already been used or has expired. Ask the person who invited you for a new one." Below the card, a `Label`-size link-style text: "Already have an account? **Log in**" (routes to `/login`) — this is the one place a link back to login belongs, since a returning user might land here by mistake.
- **Claude's discretion — defaulted:** the invalid-token state is rendered the same way regardless of *why* it's invalid (expired vs. already-used vs. malformed token) — a single generic message, per D-03's "clear ... message" requirement, without leaking which specific reason (avoids giving a token-guesser any signal).

### Book picker step (onboarding, post-invite-redemption) — D-08

- Same centered-column shell, slightly wider (`max-w-[480px]`) to comfortably fit a 7-item checkbox list without wrapping.
- `Card` (`p-6`): heading **"Pick your books"** (Heading), body (Body, 16px): "Select every Colorado sportsbook you have an account with. The finder and Arbitrage tab will only ever suggest bets at these books." Below that, a vertical list of 7 `Checkbox` + `Label` rows (one per `COLORADO_BOOKS` entry with `apiCoverage: true`, D-10), each row a full-width tappable label (`min-h-10`, matching the finder's existing "Limit hedge amount" checkbox-row idiom) so the whole row — not just the tiny box — is the tap target.
- Primary CTA (full width, accent, `h-10`): **"Continue"** — **disabled** until at least one book is checked (D-09). No "skip" option exists.
- Inline validation (only surfaces if somehow submitted with zero — e.g. a fast double-tap race): "Select at least one book to continue." (`text-destructive`, Label size, placed directly under the checkbox list).
- On submit, redirects into the main app (finder tab, default).

### Settings page (`/settings`) — D-11

- **Authenticated** route — renders **with** `AppHeader` (so Log out / navigation stay reachable) but **without** `OddsStatusBar`/`CreditBanner` (irrelevant here; this screen has no odds/credit concerns). Content uses the same `max-w-[1080px]` container as the finder/arb tabs but the actual content column is narrower (`max-w-[480px]`, left-aligned under the header, not centered — this is a normal app page, not a pre-login gate) with standard page padding (`px-4 py-12`, matching `AppShell`'s existing `main` padding).
- Structure: page heading **"Settings"** (Heading, 20px), one line of muted context below it (Label): "Signed in as {displayName} ({email})" — read-only, no edit affordance for name/email/password in this phase (owner-script-only per D-02/D-07).
- Below that, a `Card` (`p-6`) titled **"My books"** (Heading) reusing the **identical** checkbox-list component from the onboarding book-picker step (same 7 rows, same tap-row idiom) — pre-checked with the user's current selection (D-12).
- Primary CTA (accent, `h-10`, **not** full-width here — this is a settled page, not a gate): **"Save changes"**, disabled until at least one book remains checked (D-09) and enabled only while the selection differs from what's persisted (avoids a no-op save).
- On successful save: an inline confirmation appears directly below the button — `Alert` (no variant, neutral surface, same treatment as the account-risk advisory), text: "Your books were updated." — no toast library is introduced (none in the stack); the message clears the next time the checkbox selection changes.
- Validation error (attempted save with zero, defensive only): same copy as onboarding: "Select at least one book to continue." → reworded for this context: "Select at least one book to save."

### Finder — new risk advisory (D-23, CALC-06)

- The `Alert` (no variant, neutral surface, same component and exact copy as the Arbitrage tab's standing advisory in `ArbForm.tsx`) is added to `FinderForm`/`FinderScreen`, positioned **directly above the results list**, below the finder form card — mirroring the Arbitrage tab's placement exactly (card → advisory → results) so the two tabs feel like one consistent app, not two different apps bolted together.
- **Claude's discretion — defaulted:** the advisory renders unconditionally once a search has been made (same visibility rule as the Arbitrage tab: always visible above results, not dismissible, not conditional on any result existing) — consistency with 01.1 outweighs any argument for hiding it on empty results.

### Book-filtered finder/arb behavior (D-13…D-19) — no new visual pattern

- The bonus-book `Select` (finder) now lists only the user's selected books (D-13) — same `Select` component, just a filtered `bonusBooks` prop; no visual change.
- Hedge suggestions, arb legs, and the "Multiple books" popover (D-14, D-16, D-17) are filtered server-side to the user's books before reaching any existing row/popover component — no new UI element.
- **Empty state — no games covered by the user's books (D-18, new variant):** reuses the existing `EmptyState` component pattern (finder and arb both already have per-context empty states) with a new variant: heading **"No games at your books right now"**, body: "None of the upcoming games are offered at the sportsbooks you've selected. Add more books to see more opportunities." + a `Button variant="outline"` or inline link-style CTA: **"Manage your books"** (routes to `/settings`) — the only empty state in the app that links elsewhere, because it's the only one whose fix isn't "refresh" or "change your search."

### Odds-age attribution (D-21) — extends existing status-bar copy, no new component

- `OddsStatusBar`'s existing age line gains an optional attribution suffix when the triggering user is known: **"Odds updated {N} min ago · Refreshed by {displayName}"** (moneyline) and **"Spreads & totals updated {N} min ago · Searched by {displayName}"** (extended) — same `·` separator convention already used elsewhere in the app (e.g. 01.1's results caption). No attribution suffix renders when the value is unknown (e.g. legacy rows from before this phase, or `refreshedBy` not yet populated) — the line falls back to its current unattributed form, never showing a placeholder like "Refreshed by —".

### Touch targets & dark mode

- Unchanged: all new inputs/buttons/checkboxes ≥40px height (`h-10`), full checkbox-row tap targets ≥40px (same as the finder's existing checkbox row), `AccountMenu` trigger ≥40px. No new 44px exceptions introduced by this phase (no mobile result-row-style dense list appears on any new screen).
- Dark mode: unchanged — OS `prefers-color-scheme` only, no manual toggle, applies identically to the new centered auth pages and the settings page.

## Color

Unchanged palette from Phase 1/01.1 — same hex values, same light/dark pairs. The reserved-for list is **extended** (not replaced) to cover this phase's new accent-bearing elements.

| Role | Value (light) | Value (dark) | Usage |
|------|------|------|-------|
| Dominant (60%) | `#FFFFFF` | `#09090B` (zinc-950) | Page background — including the centered auth-page backdrop |
| Secondary (30%) | `#FAFAFA`, border `#E4E4E7` | `#18181B`, border `#27272A` | `AppHeader` surface, all new `Card`s (login/invite/book-picker/settings), `AccountMenu` dropdown surface |
| Accent (10%) | `#059669` (emerald-600) | `#10B981` (emerald-500) | See "Accent reserved for" below |
| Destructive | `#DC2626` (red-600) | `#EF4444` (red-500) | Login-failure alert, invite-form validation errors, book-picker/settings "select at least one" validation, rate-limit lockout message |
| Warning (amber) | `#D97706` (amber-600) | `#F59E0B` (amber-500) | Not used on any new screen this phase — no time-sensitive/stale state exists on auth or settings pages |

**Accent reserved for (exhaustive — extends 01.1's list with items 6 and 7; nothing else may use accent):**
1. "Find hedges" primary CTA fill (unchanged)
2. The guaranteed-profit dollar figure in every result row on both tabs (unchanged)
3. The active/selected chip in any single-select toggle group (unchanged)
4. The checked-state fill of the finder's "Limit hedge amount" checkbox (unchanged)
5. Input focus ring (`focus-visible` outline) on all form controls, every screen including the five new ones
6. **(new)** The checked-state fill of every book-picker `Checkbox` (onboarding step and settings page) — same "this is on" meaning family as item 4
7. **(new)** The single primary CTA fill on each new screen — exactly one accent button per screen, never more: "Log in" (login), "Create account" (invite), "Continue" (onboarding book picker), "Save changes" (settings)

**Explicitly NOT accent (Claude's discretion — defaulted):**
- The `AccountMenu` trigger button is `variant="ghost"` — plain text + chevron, no accent, no border. It's a persistent, low-stakes navigation affordance (like "Refresh odds" is a low-stakes utility action), not a conversion moment.
- **"Log out"** in the `AccountMenu` dropdown uses **default menu-item styling, not destructive/red**. Logging out destroys no data, sessions already expire after 30 days on their own (D-06), and it's a single, immediately-reversible click (log back in) — it fails the "irreversible or data-destroying" bar that reserves red for the finder's blocked-refresh/error states. This mirrors CONTEXT.md's Claude's-Discretion note that no destructive action exists in this phase.
- The "Manage your books" link/button in the D-18 empty state is `variant="outline"` or plain link styling, not accent — it's a secondary way out of an empty state, not the screen's primary action.
