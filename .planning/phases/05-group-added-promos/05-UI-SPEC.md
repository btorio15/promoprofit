# Phase 5 - UI Design Contract

> Visual and interaction contract for hand-added (personal) promos. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Non-interactive run.** 05-CONTEXT.md locks scope and flow (D-01..D-12). Tokens (spacing, typography, color, 44px targets) are inherited unchanged from 03-UI-SPEC.md and 04-UI-SPEC.md. Items marked "defaulted" were left to Claude's discretion. Added promos are personal only (D-01): there is no shared/private toggle, no "added by {name}" attribution, and no group visibility anywhere in the UI.

## Layout & Responsive Behavior

Phone-first, designed at 360px. Content stays in the existing `max-w-[1080px]` main. No new top-level tab or sub-tab: everything lives in Promos > Active.

### Add promo entry point (D-02)

- At the top of **Promos > Active**, above the sort switch, a header row: Label description on the left, **Add promo** button on the right (`Button`, accent fill, `Plus` icon size-4, min-h 44px). On 360px the row wraps and the button goes full width under the description.
- Tapping it opens the form as an **inline panel** in place, pushing the list down (same inline sub-panel idiom as Phase 3's Correct panel; no modal, no new shadcn block, so the keyboard and the ScopePicker's search work naturally on a phone). The button is replaced by the panel while open. Only one form open at a time (add OR edit).
- Panel shell: `rounded-lg border border-border bg-secondary p-4`, inner `flex flex-col gap-4`; Heading 20px title ("Add a promo" / "Edit promo"), fields stacked in one column (max field width fills the panel). On >= md the two short fields of a group may sit side by side in `grid grid-cols-2 gap-4`.
- Save/Cancel row at the bottom of the panel: `flex flex-wrap gap-2`, buttons min-h 44px.
- On save success: panel closes, list refetches, the new row appears in its ranked position (no forced scroll); a one-line inline confirmation (Label, muted, `role="status"`) shows above the list for the session: "Promo added. It's live in your Promos and Opportunities." Clears on next add or reload.

### Form fields (D-03, D-05, D-07)

One screen. Fields change with type; switching type keeps Book and any shared values, drops fields that no longer apply.

1. **Book** (`Select`, h-11): only the member's own books (D-08). If the member has no books selected: replace the form body with the "no books" empty state below.
2. **Type** (`ToggleGroup` single-select, cannot deselect, each item min-h 44px, `px-4`): **Profit boost** | **Bonus bet**. Selected item uses the accent chip style (existing rule).

**Profit boost fields** (in this order):
3. **Boost as** (`ToggleGroup`, D-06): **Boost %** | **Boosted odds**. Default Boost %. Shows one `Input` below: "Boost %" (numeric, suffix "%") or "Boosted odds" (American odds, e.g. "+250").
4. **Game(s)** (required): `ScopePicker` reused as-is (D-04): "One game" search box, or "All {league} games" with From / Through days. Never a long dropdown.
5. **Max stake** (required, `Input`, money, prefix "$"). Helper (Label, muted): "Every boost needs a max stake so the math never guesses."
6. **More details (optional)** `Collapsible` closed by default (trigger min-h 44px, chevron): Max winnings (`Input`, money) plus its kind (`ToggleGroup`: "Total payout" | "Extra winnings", reusing the cap-kind meaning the scraped boost model already stores), Min odds (`Input`, American), Market / side pin (`Select`, disabled until One game is chosen; same vocabulary as Phase 3: "Moneyline - {team}", "Spread +3.5 - {team}", "Total O/U 44.5"), Expires (`Select` or date-time as the existing scope tools provide; see below).

**Bonus bet fields**:
3. **Bonus amount** (required, `Input`, money, prefix "$").
4. **Expires** (required): date picker via `Select` of the next 30 days (Label "Expires", format "Sat, Oct 4") plus time defaulting to end of day ET (11:59 PM). Helper: "Bonus bets usually expire in 7 days."
5. **More details (optional)** `Collapsible`: Game(s) (`ScopePicker`; left unset = "any game", helper: "Leave blank and we'll find the best game to use it on."), Min odds (`Input`, American).

**Expiry for boosts (D-05):** the optional Expires field on a boost defaults to "Start of the last game" (shown as helper text "Ends when the last game starts"); the member may override with a date.

### Validation and inline behavior

- Validate on Save and on blur; errors under the field in Label size, `text-destructive`, `role="alert"`, plus `aria-invalid` on the input. First invalid field takes focus.
- Save button disabled only while saving (shows "Saving..." with `Loader2` spin); it is NOT disabled for missing fields, so errors can explain what is missing.
- Money and odds inputs use `inputMode="decimal"` (money) and `inputMode="text"` with pattern for signed American odds; all `.num`.
- Cross-field: bonus expiry in the past, boosted odds that are not better than current market odds is NOT blocked (the engine handles it), min odds outside American range, max winnings lower than max stake are allowed (different measures); no false blocking.

### Duplicate hint (D-12)

Non-blocking `Alert` (default variant, `Info` icon size-4) directly above the Save row when the draft matches a visible scraped promo (same book + type + amount/boost % + overlapping scope): "This looks like a promo already in your list." Save is still allowed and the two promos stay separate. Appears live as the fields change; never blocks, never auto-merges.

### Added promo rows in lists

- Added promos render in the existing `PromoRow` (Active, Opportunities Best promos, Done) with no layout change.
- Marker: a `Badge variant="outline"` reading **Added by you** placed next to the promo-type badge in Col 2 (neutral, not accent). Also on the Done row.
- Added promos are never subject to review/"Auto-matched"/"Cap entered by" attribution; the expanded panel shows no scrape source line. Instead its expanded panel shows a Label muted line: "You added this promo." plus the actions row below.
- **Row actions (own added promos only)**, in the expanded panel under the steps, `flex flex-wrap gap-2`, each min-h 44px:
  - **Edit** (`Button variant="outline"`, `Pencil` icon): closes any other form and opens the same form prefilled, in the inline panel at the top of Active (scrolls it into view). Type and Book are locked while editing (Label under them: "Book and type can't be changed. Delete this promo and add a new one instead."). Save label **Save changes**.
  - **Expire now** (`Button variant="outline"`, `Clock` icon): opens `AlertDialog` (see copy). Sets the promo expired; it leaves Active and Opportunities immediately. Not shown for already-expired promos.
  - **Delete** (`Button variant="outline"`, `text-destructive`, `Trash2` icon): opens `AlertDialog` with destructive confirm.
- Whole-row triggers, badge, and chevron behavior unchanged. Action buttons are inside the expanded panel so they never conflict with the row trigger, and no `stopPropagation` hacks are needed.
- A hand-added promo that has passed its expiry, or whose game has started, drops out of Active like a scraped one; there is no separate "Expired" list this phase. Its Done entry (if any) persists (D-11).

### Delete and Done history (D-11)

- Deleting a promo already marked done never removes its Done entry or its profit: the Done row keeps rendering from its snapshot and Total profit extracted is unchanged. The delete dialog for a done promo says so (copy below); a promo that is NOT done deletes cleanly with no effect on totals.
- A done row whose source promo was deleted shows no Edit/Delete/Expire actions (nothing to act on) and no "Added by you" link-back; the badge stays.

### Loading, saving and error states

- Save in flight: form fields stay visible, button shows spinner, fields `disabled`. No optimistic list insert; the row appears after the server confirms and the list refetches.
- Save failure: inline `Alert` (destructive) at the top of the panel; form values are kept.
- Server-side scope validation failure (game gone, window invalid): inline field error on Game(s).
- Delete/expire failure: the dialog closes and an inline destructive `Alert` shows above the list; row unchanged.

### Empty states

All use the `EmptyState` shell (`rounded-lg border border-dashed border-border bg-background p-6`).
- **No books selected** (inside the open form): heading "Pick your sportsbooks first", body "You can only add promos for books you have. Add your books in settings." CTA `Button variant="outline"` -> `/settings`: "Manage your books". The Add promo button itself stays enabled so the reason is discoverable.
- **Existing Active empty states** (03/04 copy) gain a secondary line only when the tab is otherwise empty: "Seeing a promo in your app that isn't here? Add it yourself." and the Add promo button remains at the top (no second CTA inside the empty state, avoids two identical buttons).

### Touch targets & dark mode

All new buttons, toggle items, selects, inputs and collapsible triggers are min 44px (same standard as Phase 4). Dark mode: OS `prefers-color-scheme` only, unchanged. Focus order follows visual order; on open the panel focuses the Book select; on close focus returns to the Add promo button (or the row's Edit button when editing).

## Color

Unchanged palette.

| Role | Light | Dark | Usage |
|------|-------|------|-------|
| Dominant (60%) | `#FFFFFF` | `#09090B` | Page background |
| Secondary (30%) | `#FAFAFA`, border `#E4E4E7` | `#18181B`, border `#27272A` | Form panel, rows |
| Accent (10%) | `#059669` | `#10B981` | See list |
| Destructive | `#DC2626` | `#EF4444` | See list |

**Accent reserved for (exhaustive, extends 03/04 lists):**
1. **Add promo** button and the form's **Save promo** / **Save changes** button (the primary CTA of this phase; only one accent button visible at a time, because Add promo is replaced by the panel while it is open)
2. Selected item of the Type and Boost-as toggle groups (existing "active chip" rule)
3. Guaranteed-profit figures in rows (unchanged)
4. Focus rings, checked checkboxes (unchanged)

**Destructive reserved for:** field validation errors, save/delete/expire failure alerts, the **Delete** action button text (outline variant) and the **Delete promo** confirm button. **Expire now** is NOT destructive (it is reversible by re-adding, and does not erase history), confirm button is default (neutral) style.

Explicitly NOT accent: "Added by you" badge, Edit, Expire now, duplicate-hint Alert, Cancel, "More details" trigger.
