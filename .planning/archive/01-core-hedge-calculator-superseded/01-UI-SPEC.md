## Layout & Responsive Behavior

(Not in the base template — added because Phase 1's CONTEXT.md explicitly requires "reasonably usable at phone width" while mobile-optimization itself is deferred to DASH-06.)

- **Structure:** One page, one form. Two-leg form (Leg A / Leg B) per D-13, market-type select above the legs, results panel below/beside the form.
- **Mobile (< 1024px, default/mobile-first):** Single column. Order top→bottom: page title → market-type select → Leg A card → Leg B card → results panel (appears once form is valid) → advisory footnote. Full-width inputs and buttons.
- **Desktop (≥ 1024px, `lg:` breakpoint):** Two-column grid — form (Leg A/B + market select) in a left column (`~55%` width), results panel in a right column (`~45%` width, `sticky top-6`) so results stay visible while editing.
- **Touch targets:** All inputs, selects, toggle-group segments, and buttons minimum 40px height (`h-10`) regardless of breakpoint — satisfies "reasonably usable at phone width" without building the deferred mobile-optimized layout.
- **Dark mode:** Class-strategy dark mode (Tailwind `dark:` + shadcn CSS variables), driven by OS `prefers-color-scheme` on first load. No manual theme-toggle control required in Phase 1 scope — Claude's discretion — defaulted.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, inline badge padding |
| sm | 8px | Compact spacing: input helper text to input, table cell padding |
| md | 16px | Default spacing: form field stacking, card internal padding |
| lg | 24px | Section padding: leg-card padding, results-panel padding |
| xl | 32px | Layout gaps: gap between form column and results column (desktop) |
| 2xl | 48px | Major section breaks: page header to form, form to advisory footnote |
| 3xl | 64px | Page-level spacing: top/bottom page margins on desktop |

Exceptions: none — the 44px "icon-only touch target" exception in the base template is not needed here; all Phase 1 controls are labeled (no icon-only buttons), and the 40px (`h-10`) minimum control height already satisfies touch usability at the 8-point scale (40 = 8×5).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 400 (regular) | 1.5 |
| Body | 16px | 400 (regular) | 1.5 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 36px | 600 (semibold) | 1.2 |

- Exactly 4 sizes, exactly 2 weights (400 regular, 600 semibold) — no other sizes/weights permitted in Phase 1 UI.
- **Label (14px):** form field labels, table headers, per-outcome table body cells, footnote/advisory text, book/outcome free-text labels (D-14).
- **Body (16px):** input values, form helper/validation text, results panel supporting copy (conversion/ROI %, cap-clamp explanation).
- **Heading (20px):** section titles ("Leg A", "Leg B", "Results").
- **Display (36px):** the single headline number — guaranteed profit in dollars (D-09). This is the only Display-size element on the page.
- **Numeric formatting:** every dollar figure, odds value, and percentage renders in `Geist Mono` with `font-variant-numeric: tabular-nums` so digits align in the per-outcome table (D-10) and don't jitter as the user types (D-08 live validation).

## Color

Both light and dark values given — the calculator must work in both (per CONTEXT.md notes).

| Role | Value (light) | Value (dark) | Usage |
|------|------|------|-------|
| Dominant (60%) | `#FFFFFF` (white) | `#09090B` (zinc-950) | Page background |
| Secondary (30%) | `#FAFAFA` (zinc-50), border `#E4E4E7` (zinc-200) | `#18181B` (zinc-900), border `#27272A` (zinc-800) | Leg A/B cards, results panel surface, per-outcome table zebra rows |
| Accent (10%) | `#059669` (emerald-600) | `#10B981` (emerald-500) | See "Accent reserved for" below |
| Destructive | `#DC2626` (red-600) | `#EF4444` (red-500) | Inline validation errors only (D-08) |
| Warning (Phase 1 addition) | `#D97706` (amber-600) | `#F59E0B` (amber-500) | Whole-number push-line warning (D-15), cap-clamp explanation (D-03), account-risk advisory icon (D-12/CALC-06) |

Accent reserved for (exhaustive list — nothing else may use accent color):
1. Primary CTA button ("Copy link") background/fill
2. The headline guaranteed-profit dollar figure (Display, 36px) — the one number the whole page exists to show
3. The active/selected segment in each leg's Plain / Bonus bet / Boost toggle-group (D-13)
4. Input focus ring (`focus-visible` outline) on all form controls

All other UI (labels, body text, card borders, table borders, disabled states) uses zinc neutrals only.

Color-palette rationale: emerald reads as "profit/green" without requiring a second semantic meaning beyond the accent role; amber is reserved for advisory/caution states that are not blocking errors (push warning, cap clamp, account-risk note) so they're visually distinct from red validation errors.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **Copy link** — copies the current calculation's shareable URL to the clipboard (ties to D-16, URL-persisted state); button shows a brief "Copied" confirmation on click |
| Empty state heading | **Enter both legs to see your hedge** |
| Empty state body | "Choose a bet type and enter odds for Leg A and Leg B — your guaranteed profit appears here once both sides are valid." (shown in place of the results panel until D-08's validity check passes) |
| Error state (field-level) | Inline, under the offending field. Odds: "American odds must be +100 or higher, or −100 or lower." Amount: "Enter an amount greater than $0." |
| Error state (form-level) | "Fix the highlighted fields to see your hedge calculation." (shown only if the user has touched at least one field) |
| Push-line warning (D-15) | "Whole-number lines can push (tie), which breaks the guarantee. Use a half-point line or switch to Moneyline." |
| Cap-clamp explanation (D-03) | "Stake reduced to $[X] — above this, boosted winnings are capped at $[Y]." |
| Account-risk advisory footnote (D-12/CALC-06) | Collapsed: "Precise, promo-optimized stakes can lead to sportsbook account limits. **Learn more**" (expander) |
| Account-risk advisory expanded body | "Sportsbooks track betting patterns and may limit or restrict accounts that consistently bet mathematically optimal, promo-only stakes with little variance from normal bettor behavior. This calculator shows you the optimal hedge — how much promo activity to run, and on which accounts, is your call." |
| Results headline label | "Guaranteed profit" (above the Display-size dollar figure) |
| Results sub-metric label | "Conversion" (bonus-bet legs, profit ÷ bonus amount) **or** "ROI" (cash/boost legs, profit ÷ cash risked) — never mislabeled per D-09 |
| Per-outcome table headers | "Outcome" · "Bet" · "Payout" · "Net profit" |
| Reset action | **Reset form** — clears all entered values and resets the URL to its base path. No confirmation dialog: this only clears unsaved, in-session form state (nothing is persisted in Phase 1 — no saved promos yet), and the previous state remains one browser-back away since state lives in the URL (D-16). |
| Destructive actions in this phase | None that touch persisted data (no save/delete of promos in Phase 1 — that's PROMO-05, Phase 3). "Reset form" above is the only clearing action, treated as low-stakes per the note above — not a true destructive-confirmation case. |
